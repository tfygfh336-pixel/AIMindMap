#### ① `related --depth 2`：两跳邻域（承接被否决的全量图谱）
- `src/relations.js` 重构并新增能力：
  - **`backlinkIndex(projects)`**：一次遍历建「`项目|节点id` → 引用者」索引。
    原先 `backlinksAll` 每个目标都要扫全部项目；depth 2 要对每个一跳邻居再求一次邻域，
    逐次全量扫描是 O(N·M)，故必须先建索引。
  - **`backlinksFrom(index, ...)`**、**`nodeIndex(projects)`**：配套的查表函数。
  - **`relatedAll(..., {depth: 2})`**：把一跳邻域再向外扩一跳。二跳项带
    `depth:2` 与 `via:{project,node,topic}` —— **二跳的方向是相对中间节点的**，
    不带 `via` 无法正确解读，故必须携带。
  - 返回结构新增 `depth1Count` / `depth2Count`；`outCount`/`inCount` **仍只统计一跳**
    （保持"直接引用数"的既有语义不变）。
- 设计取舍（写进代码注释）：depth 只认 1 与 2，其他值退化为 1 —— **不做无界展开**。
  这是"局部图"而非"全量图"，全量图已在 `docs/ROADMAP.md` 否决（孤点占比 2/3）。
- CLI `related <项目> <id> [--depth 2]`（registry usage 已更新，MCP 工具加 `depth` 参数）。
  文本输出把一跳与二跳分开，二跳按「经由谁」分组 —— 否则远近混在一起看不出层次。
- **实测**（comnet）：`related comnet tcp-handshake --depth 2` 从 2 条（一跳）扩到 7 条，
  揭示出「TCP 连接管理 → 接口 TCP 可靠传输/概述 → HTTP、邮件、FTP、多路复用」这个知识簇 ——
  正是"直接关联看不出、二跳才看得见"的价值。
- 单测 `tests/relations.test.js`：10 → **22 用例**（新增两跳链路、不绕回自身、
  近者优先、跨项目二跳、depth 非法值退化、索引函数等）。

#### ② `mentions --cross`：跨项目「未链接提及」
- `src/mentions.js` 新增 **`findCrossMentions(projects, selfProject, opts)`**，两个方向：
  - **out**：本项目正文提到其他项目的节点 → 可补一条指向外部的链接
  - **in**：其他项目正文提到本项目的节点 → 可从外部补链接到本项目
- **同名歧义不猜**：跨项目才会真正出现"同一句话可能指多个同名节点"。
  本模块照报所有候选并标 `ambiguous:true`，另在 `ambiguousTopics` 汇总，
  交由人决定。猜错会写出错误的链接，丢掉则永远发现不了 —— 两者都比"报出来并标记"更差。
- 两个必要的过滤（都有理由）：
  1. **已声明链接必须拼 `project` 比对**：只比 `id` 会让本项目的同名 id 掩盖跨项目漏链。
  2. **节点正文提到自己的主题名属自指**，不算"提到了别处那个同名节点"（跨项目常见假阳性）。
- `findMentions` 的每项新增 `direction:'same'`（附加字段）—— 使本项目内与跨项目的项
  **形状统一**，调用方不必分支处理。
- CLI `mentions --cross`、MCP 工具加 `cross` 参数。
- 单测 `tests/mentions.test.js`：12 → **26 用例**。

### 拆分 `renderer/app.js`（1340 行 → 7 个模块，最大 281 行）（2026-09-16）

> **措辞更新（复审时按当前真值更正）**：本节（标题 / 正文 / 表格）记的都是**拆分当时**的快照。
> 此后渲染层又新增 `app-audit.js`、`app-palette.js`，现状为入口 `renderer/app.js`（199 行）
> + **9 个 `app-*.js` 模块**（app 家族共 10 个文件），最大文件 `app-detail.js` **303 行**。
> 历史行数保留原样（它们是当时的实测值），不再代表现状。

**问题**：`renderer/app.js` 单文件 1340 行，承担了项目加载、jsMind 生命周期、视图变换、
浮动详情框（创建/拖动/改大小/锚点/锁定/看护）、图片灯箱、附件预览、搜索、撤销重做、
节点增删改、工具栏接线 —— 改动任何一处都要在千行文件里定位，是后续所有界面改动的成本来源。

**做法（纯搬移，零行为变更）**：拆为 7 个模块，全部挂在共享命名空间 `window.MM` 上，
`renderer/app.js` 只留 `wireUI()` + `window.MMApp` 导出 + 启动：

| 文件 | 行数 | 职责 |
|---|---|---|
| `app-core.js` | 177 | **最先加载**：初始化 `window.MM`、共享状态、序列化 `serializeTree`、`renderMind`、纯函数助手、`setStatus` |
| `app-view.js` | 268 | 画布视图：统一 transform 平移缩放、视口接线、居中/还原、主题模式、展开收起 |
| `app-detail.js` | 281 | 浮动详情框池：创建/复用/关闭、跟随锚点、小锁/大锁、逐帧看护、`showDetail` |
| `app-detail-drag.js` | 143 | 详情框拖动与改大小、图片悬停提示 |

| `app-media.js` | 134 | 图片灯箱、附件预览、`renderRelated`（相关知识点面板） |

| `app.js` | 137 | `wireUI()` + `window.MMApp` + `DOMContentLoaded` 启动 |

**保持"函数体逐字不变"的手法**：拆分前所有函数在同一个 IIFE 闭包里互相裸调用。
现每个模块顶部只为「定义在其他文件」的函数声明**转发包装**（`const renderMind = (d) => MM.renderMind(d);`，
用包装而非解构 —— 其他模块是后加载的，解构会在加载时捕获 `undefined`），
于是**函数体内原有的裸调用一处都不用改**。这也是为什么本次能保证行为零变化。

**一个必须说明的取舍**：`fdView` / `fdHideRootLinks` / `fdDrag` / `fdResize` 这 4 个变量
**会被整体重新赋值**（如 `fdView = { x: 0, y: 0, s: 1 }`），而转发包装只能转发"读"、
无法把赋值写回另一个文件的闭包变量。故这 4 个用**与拆分前同名**的全局槽位承载
（`window.fdView` 等，声明于 `app-core.js`）—— 函数体仍是裸名读写，一个字符未改。
- 已核实：页面 `index.html` **不存在**与这 4 个名字同名的元素 id（浏览器的 id→全局变量机制不会冲突）；
- 它们的读写只发生在事件回调与渲染时，不在模块求值时，故与脚本加载顺序无关；
- 行为已由现有冒烟断言覆盖（主题模式、平移缩放、拖动/锁定详情框），非"无人看管"。

**验证（全部为独立复跑，非一次性）**
- 拆分前 `app.js` 的 **82 个函数体与 53 段块注释逐字比对通过**；原文件除 4 行 `let` 声明外

### CLI 纯逻辑下沉到 src/ + 命令层首次获得单测覆盖（2026-09-16）

**要解决的问题**：命令层（`cli/commands/*`）此前**零单测** —— 它承载着"AI 到底看到什么"
这类最关键的逻辑（read 视图形状、search 命中判定、stats 计数、打包格式解析、版本号递增），
却只能靠端到端断言间接覆盖。改一处细节要跑整条集成链才能知道有没有坏。

**新增三个 `src/` 纯逻辑模块**（UMD，无 IO，可被单测直接覆盖）：

| 新模块 | 下沉自 | 覆盖内容 |
|---|---|---|
| `src/query.js` | `cli/commands/project.js` | `buildReadView`（read --json 视图）、`buildNodeList`、`getNodeView`、`computeStats`、`searchNodes`、`collectImages`、`treeLines` |
| `src/bundle.js` | `cli/commands/project.js` | aimap v1 打包格式：`buildBundle`/`parseBundle`/`collectResourceRefs`/`isSafeRelPath`/`resourceUsageCount` |
| `src/version.js` | `cli/commands/release.js` | 版本号 `isValid`/`parse`/`bump`/`compare` |

命令文件随之只剩"读参数 → 调纯逻辑 → 输出"，`project.js` 的 `buildReadView` 变为一行转发。

**顺带修掉三个真实缺陷**（都是下沉过程中由新单测暴露的）：

1. **`release --minor` 不把 patch 归零**：`0.14.3 --minor` 会得到 `0.15.3`，
   违反语义化版本定义（应为 `0.15.0`）。
2. **`release` 完全没有 `--major`**，且 registry 的 usage 只声明了 `--patch|--minor`。
3. **`release` 允许版本倒退**：可以把 `0.15.0` 发到已存在的 `0.16.0` 上，

### 规则体系重构：从"铁律清单"改为"门禁 + 铁律 + 约定"三级结构（2026-09-16）

### 【数据安全】冒烟测试改为在隔离的项目副本上运行（2026-09-16）

**发现的问题：验证命令会写真实用户数据。**
在核对数据完整性时发现 `projects/comnet/comnet.json` 的 **mtime 每次跑 `npm run smoke` 都会变**。
定位到 `scripts/smoke-assertions.js` 的「undo/redo roundtrip」断言：
它为验证撤销重做而调用 `app.save()` **两次**，且直接运行在**真实项目**上。

- 内容层面：断言结束时会移除临时节点并再保存一次，最终内容与原始一致
  （实测 SHA256 不变），所以此前没有造成可见损坏。
- **风险层面（真正的问题）**：`npm run verify` 每次都在重写用户笔记文件；
  一旦进程在"加了临时节点并保存"与"移除并保存"之间崩溃/被强杀，
  真实笔记里会**永久残留** `smoke-undo` 节点。任何测试都不该触碰真实数据。

**修复：不再逐条去改断言，而是从根上隔离整个项目根。**
- `main.js` 在 `--smoke` 时把项目根重定向到 `os.tmpdir()` 下的临时目录
  （`ai-mind-map-smoke-*`），并**先把真实 `projects/` 复制一份**进去；
  退出（`will-quit` / `process.exit`）时删除临时目录。
- 之所以选"整体重定向"而非"删掉那两行 `app.save()`"：断言里的项目路径全部经
  store/IPC 获取（`openProject('comnet')`、`p.file` 等），重定向后**无需改动任何断言**，
  且今后任何新增的写盘型断言都自动被隔离 —— 消除的是整类风险，不是一个实例。
- **验证**：修复后 `comnet.json` 的 mtime 在冒烟前后**完全不变**，hash 一致，
  临时目录零残留；45 条冒烟断言（含项目相关的全部）依然通过。
- 新增冒烟断言「冒烟运行在隔离的项目副本上（不写真实数据）」守住该不变量：
  它检查当前项目文件路径是否位于沙箱目录内。若有人日后去掉隔离，该断言立即变红。

**测试与验证**
- 冒烟：44 → **45 断言**。
- `npm run verify` 全绿，且不再修改 `projects/` 下任何文件。

**顺带**：`.gitignore` 补 `smoke-out.txt`（冒烟输出重定向的调试日志，非源码）。

### 正确性修复 + 监听器泄漏 + 版本单源 + 打包/忽略修正（2026-09-16）

### 写盘原子化（数据安全批次）+ 存取层单测 + 测试池修正（2026-09-16）

**背景（本次发现的真实缺陷）**：`docs/DATA-FORMAT.md` §5 与 `docs/ARCHITECTURE.md` 模块表此前均承诺「写盘走原子写（临时文件 + 校验通过后 rename）」，但 `src/data-store.js` 实际是**裸 `fs.writeFileSync`** —— 只有渲染层的 `project:save` 这条 IPC 做了 temp+rename，**32 条 CLI 命令的所有写操作都不是原子写**。
对照实验（同一注入故障：写入过程抛错）实测后果：
- 旧实现：目标文件被截断 → **无法 `JSON.parse`** → 整库损坏；

### 统一视图变换，根治「放大显示不全」+ 主题连线精确独立（2026-09-15）

**用户反馈**：① 容器根消失、标题变左上角角标 ✓；② 开启主题模式后，新增顶层主题仍与后面的节点连线；③ 放大之后仍显示不全（之前只隐藏了滚动条，jsMind 的滚动效果还在）。要求先分析、定方案再改。

- **根因 ①（双坐标系冲突，与历史经验 765519 同类）**：jsMind 原生用「`e_panel.scrollLeft/Top`（滚动）+ 子元素 `style.zoom`」实现平移缩放，而我们又在**外层**叠了一套 `transform: translate`。放大后内容超出面板，jsMind 想靠滚动把内容移到指针下，但滚动范围受限（横向尤其不够），外层 transform 再叠加一次 → 部分内容落在「滚动够不到、平移也不对」的位置。期间曾尝试 `foldScrollIntoPan()`（把滚动折算进平移），但滚动与 transform 作用对象不同（移动内容 vs 移动视口），jsMind 在 show() 后还会异步再改滚动，双重偏移反而把画面推出屏幕，**该方案已废弃**。
- **修复 ①：单一变换层**。引入 `fdView={x,y,s}`，只用**一个** `transform: translate(x,y) scale(s)`（origin 0 0）同时作用在 `canvas.jsmind` 与 `jmnodes`（线与节点永不错位）；**完全不再调用 jsMind 的 zoom/scroll**（`zoom_current` 仅置为 s 供读数，`scrollLeft/Top` 恒 0，`neutralizeScroll()` 吸收残留滚动）。
  - 滚轮缩放 `zoomViewAt`：标准指针锚点公式，步长 0.1，范围 0.15–4；中键平移只改 `(x,y)`，无界、四向对称。
  - 兼容层：`jm.view.set_zoom/zoom_in/zoom_out` 转发到统一 transform（保留既有调用契约，不走原生 zoom+scroll）。
  - `bindViewportControls()` 全局只绑一次 wheel/鼠标/scroll（修掉重复建图时重复注册 document 监听、"滚一格变两档"的隐患）。
  - `resetView()` = s 回 1 + `centerOnRoot()`（先应用当前 s、再据真实矩形测量居中）。
- **根因 ②（连线判定用错坐标系）**：旧实现用「DOM 矩形 + hmargin」猜端点（屏幕坐标），而 `show_lines()` 端点是**布局坐标**，故 6 条线只蒙对 1 条。
- **修复 ②：按父子关系精确跳过**。重写 `jm.view.show_lines()`（复刻原实现，仅多一句判断）：主题模式下凡 `t.parent.isroot` 的线直接跳过，**不触碰节点 DOM**（区别于曾导致节点全消失的 `view.reset()`）。切换/新增主题即时生效：实测 `skippedThemes=6`（=根子女数）、切回单中心 `skippedTree=0`、根重新显示。

### 力导向布局塌陷修复（2026-09-15）

用户提供截图：`comnet` 图谱只显示 **4 个节点标签**、分居画布四角、连线连成一个巨大的 X。

- **根因**：`forceLayout` 原实现是"斥力 `k²/d` 累计进速度 → `×0.85` 阻尼 → 移动"，**既无位移限幅/温度退火，向心引力又比斥力小约 450 倍**。近距离斥力（k≈144 → k²≈20850）把速度顶到**平均 439,426 px/步**，节点一路飞出画布被 `Math.max(28, Math.min(w-28))` 夹到四角 → 44 节点塌成 4 堆（诊断实测：不同坐标数仅 4~5、最大堆叠 12~14）→ 贪心标签避让只在每堆里画出度数最高的那 1 个标签。此即"44 节点全灰点挤在中心"之后暴露的**第二个布局缺陷**，且只有真实有边数据（本次新增 47 边）才会触发，此前力导向分支从未被真实数据走到。
- **修复**（重写为标准 FR 力模型）：
  1. **位移限幅 / 温度退火** `lim = min(disp, temp)`，`temp` 由 `min(w,h)*0.1` 线性降到 0.6 —— 缺此步即爆炸；
  2. **斥力截断** `d > 3k` 直接忽略 —— 斥力局部化，否则点云必被撑到边界（实测所有旧配置包围盒恒等于可夹取区 1367×655）；
  3. **引力提到同量级** `grav = 0.03k`（原 `0.008` 与斥力差约 450 倍）；
  4. **FR 引力 `d²/k`** 取代线性弹簧，随距离平方增长，天然约束布局范围；
  5. **收尾松弛**：最多 120 轮只解重叠、不动整体结构，保证标签不互相压；
  6. **`minD` 随画布自适应** `min(52, max(28, min(w,h)/12))`，小画布不再出现不可满足的约束。
- **参数是扫出来的、不是拍脑袋**：对 `comnet` 真实数据（44 节点 / 47 边）扫描 9 组配置后取 `理想边长系数 0.9 / 斥力截断 3k / 引力 0.03k / 防重叠 52px / 温度 0.1·min(w,h)→0.6 / 迭代 300 / FR 引力系数 0.8`。
- **新增回归断言** `force layout spreads nodes (no corner collapse)`：校验不同坐标数≈节点数、贴边占比 ≤20%、最近邻间距 ≥20px。真实应用实测 **`{nodes:44, distinct:44, maxPile:1, onEdge:0, minPair:73}`**；修复前该断言必失败（`distinct:4~5, maxPile:14, onEdge:44, minPair:0`）。冒烟 **22 → 23** 断言。
- **目视确认**：`smoke-shot.png` 现为正常辐射状网络——44 个标签清晰铺开、47 条边正确连接、图例与标签着色生效。
- 验证：`node --check` 通过；`npm test` **38/38**；`node scripts/cli-integration.js` **44/44**；`npm run smoke` **23/23**；`validate-all` 通过。
