## 二、修复清单（按严重度）

### 数据安全类（可能丢数据 / 写盘必失败）
| # | Bug | 影响 | 修复 |
|---|-----|------|------|
| 1 | **`moveNode` 防环失效**：防环检查依赖 `parent` 指针，但 `linkParents` 在工程中从未被调用 | `move b c`（b 移到自己子孙下）成功执行，子树从树中断开**彻底丢失**，validate 不报错 | 改用 `pathTo` 判断目标路径是否含被移节点；成环移动被拒 ✓ |
| 2 | **schema 环检测栈溢出**：递归 `validateNode` 遇环先崩，检测逻辑执行不到 | 含环数据校验直接 RangeError | `validateProject` 顶层先迭代验环（对象引用 Set），再递归校验 |
| 3 | **schema 重复 id 检测失效**：单 Set 同时存对象与 id 字符串互相冲突 | 重复 id 校验永远通过 | 拆 `seenNodes`（对象）+ `seenIds`（id）双集合 |
| 4 | **`parseArgs` 把 `--detail` 硬编码为 flag** | `add/edit --detail "<值>"` 永远把 detail 设为 `true`，写盘校验必失败——**README 示例一直是坏的** | 移除显式 flag 行，通用分支自动兼容"带值"与"flag"两种语义（read/get 用法不受影响） |

## 四、架构优化建议（提高可维护性 / 可迭代性）

### A. 防丢失（最高优先级——两次事故的教训）
1. **工程外备份机制（建议立即做）**：新增 `npm run backup`——把 `projects/`、双文档、SKILL.md、docs/ 复制到**工程外**目录（如 `%USERPROFILE%\Documents\AI-MindMap-Backups\<时间戳>\`）。原因：EDR 清的是 `.user_skills` 内批量写盘/移动，工程外复制不受影响；不依赖 Git。
2. **大改前 export-json 兜底**：每次涉及大量节点增删前，先 `export-json` 一份到工程外（单文件含全部图片，可整体回滚）。
3. **Git 解锁（需企业侧配合）**：已知 git init 成功但写 `.git/objects` 被 EDR 拦截。需亚信安全控制台为本机/本目录加排除规则。解锁后即可提交历史回滚。
4. **避免高危操作**：禁止 robocopy /MOVE 移动 `.user_skills` 内目录；禁止批量 writeFileSync 脚本（已写入 AI-GUIDE 防丢失铁律）。

### B. 可维护性（本次已落地 + 后续建议）
1. ✅ **测试分层**：单测（核心模块 30 例）→ CLI 集成（26 命令 29 断言）→ 冒烟（渲染层 9 断言）→ 数据校验。改动任何一层都有对应回归入口。
2. ✅ **单一真源**：数据只有 JSON 节点树；CLI 是唯一写入口（校验闸门）；MCP 只转发 CLI 不复制逻辑。
3. ✅ **文档铁律**：README（架构/模块表/快速开始）+ CHANGELOG（变更轨迹）+ AI-GUIDE（AI 操作规范）+ docs/CLI.md（自动生成）。
4. ⏳ **版本号单源化**：`src/config.js` 的 `APP_VERSION` 与 `package.json` version 双处维护（当前一致，但会漂移）。建议：`config.js` 删除写死的版本，渲染层用既有 IPC `app:version` 读取。
5. ⏳ **孤儿资源清理**：`remove-image` 不删物理文件，network 现有 2 个孤儿 png。建议 CLI 增加 `prune`（列出/删除未被引用的 assets 文件）。
6. ⏳ **残留旧目录**：`.user_skills\network-mind-map\`（v0.1.0 旧工程 + comnet 旧副本）仍在，会与 ai-mind-map 重复注册 skill。**建议删除**（待用户拍板；删除是高风险操作，需用户确认）。

### C. 可迭代性（AI 驱动的关键）
1. ✅ **CLI 即 API**：26 条命令覆盖全部数据操作，AI 无需碰 GUI。
2. ✅ **MCP 标准化**：20 工具走标准 stdio 协议，DeepSeek Harness/Claude/Cursor 直接配置即用。
3. ✅ **集成测试防回归**：新命令必须加断言（AI-GUIDE 已立规）——AI 每次迭代后一键 verify，不会悄悄破坏旧功能。
4. ⏳ **发布流水线半自动**：release（版本号/文档段落）已自动化；dist 打包需手动 `npm run dist`。可后续加 `publish` 脚本（verify 全绿后自动打包）。
5. ⏳ **SKILL.md 瘦身**：当前 SKILL.md body 偏长（含工程全貌）。按 skill 规范可把 CLI 细节进一步移入 `docs/AI-GUIDE.md`（SKILL.md 只留触发与导航）——收益中等，非紧急。

### D. 不建议做的（避免过度设计）
- **不引入数据层 ORM/数据库**：JSON 文件即数据库，单项目 < 1MB，引入框架只会增加依赖与风险。
- **不做实时协作**：多人同时编辑走"export-json 传递 + 本地维护"，跨 AI 工具协作靠文件交换，与用户"单机笔记"场景匹配。
- **不把 UI 框架换成 React/Vue**：jsMind 0.9 直接操作 DOM 的模式已稳定且冒烟覆盖，重写收益低于风险。
