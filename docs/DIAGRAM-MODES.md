> **需求真源**（唯一）：用户 2026-10-26 原话 ——「参考 `diagram-generator-dev-prompt.md`（外部任务书），你的复杂结构模式的画图能力应该需要支持里面提到的功能。并且我考虑这样做：**一种复杂结构模式支持里面所有的功能，然后再开发多个其他模式比如现在的思维导图的模式，每种模式只提供它需要的那些画图功能，来提高易用程度**。为这份功能设计在项目的文档架构里写好相关内容，比如在待做的文档里写好计划细节」。
> 拆三句：**D1** 复杂结构模式支持任务书里的**全部**画图功能 · **D2** 再开发**多种模式**，每种**只暴露它需要的能力** · **D3** 把设计写进文档架构，**待做计划要有细节**。
>
> **本文回答三个问题，且只回答这三个**：① 有哪些**能力**（§2，每条带判据）② 哪个**剖面**开哪些能力、关掉的**为什么关**（§3）③ 怎么**做到**、怎么算**做完了**（§5–§7）。
> 不写实现代码；不写进度（那是 `CHANGELOG.md`）；不写数据字段契约（那是 §6 说明"将来怎么扩"，改契约是另一批的事）。

## 0. 一屏结论

1. **只有一份数据模型、一份能力目录**。所谓"模式"是一份 **剖面（profile）**：开哪些能力 + 每个能力内的**取值收窄** + 由此生成的**控件面**。它不是第二套数据 —— 这是"同一个项目能被不同模式打开"的前提（§4.1、§6）。
2. **「复杂结构模式」= 唯一全开的剖面**。它的可判形式只有一条：**矩阵里这一列没有 ✗**（可以有 ○ = 支持但默认关）。这是 D1 的机械判据，不是形容词（§3.4 不变量①）。
3. **「提高易用程度」的可判形式只有一句**：该模式的界面与命令里**不出现**它不需要的控件与参数；且控件集合由剖面**生成**，不许手写 `if (mode === …)` 分支（判据在 §4.3：`[data-cap]` 集合逐条等于剖面展开集合）。
4. **与 jsMind 的关系 = 并存**（窄模式继续用 jsMind，全模式**新建**独立 SVG 渲染器，同一份 JSON，一个剖面开关）。理由与"什么时候该收敛回去"的触发条件在 §5。**不做替换**、**也不把全模式塞进 jsMind** —— 两个方向的理由都是硬事实，不是偏好。
5. **数据落点 = 顶层可选的 `graph` 附加层，节点字段一个都不加**。实测两条（`.review/20261051-图能力模式体系/probe-graph-keys.js`）：今天的 `validate` 对**未知顶层键**和**未知节点字段**都**静默通过**（两档 exit 0），而 `renderer/app-core.js` 的 `serializeTree` 是**手挑字段白名单** ⇒ 写进节点的坐标会在界面下一次保存时**静默消失**（该文件里已有 `qa` / `localPath` / `origin` / `items` 四次同型事故的记录）。所以"写在节点上"既没人校验、又会被抹掉，是最坏的选项。

## 1. 三个词（后面全篇按这三个定义读）

### 1.1 能力（capability）

一个**可独立开关的最小单元**，且**判据唯一**：§2 表的一行 = 一条能力 = 一条"怎么算支持了"。拆分的粒度判据是这一句：**两条能力能不能分别开关？**——能，就拆开。

- 「端口锚点」与「正交布线」是两条：有端口锚点的图可以不跑 A*（直线连接也认端口）。
- 「层带」与「容器」是两条：容器是"框住一组节点"，层带是"整幅图按层分区的背景"。
- 「交叉 overpass」依赖「正交布线」（没有正交路径就没有"同一点交叉"这件事）—— 依赖写在行的判据里，不另立一列。
- **【必备】= 判据必须成立，不是可选能力**（实现可以换，判据不许没有）。只有四条：文本永不溢出（`C-F1-05`）、布局输出稳定（`C-F4-04`）、导出前溢出检测（`C-F5-04`）、条目层往返不变式（`C-I-04`）。它们在任何剖面里都必须 ✓（§3.4 不变量②）。

### 1.2 剖面（profile）

一份声明：**开哪些能力 + 每个能力内的取值收窄 + 由此生成的控件面与命令参数**。剖面**不携带数据**。

- 剖面标识符用**机器用的小写英文**（`profile: complex | mindmap | path | logic | module`）。**中文产品名不在本文命名** —— 命名权在用户（`docs/FEATURES.md` §2 第 3/6 条：新名字要用户点头，代理不许先起名再用）。已存在的两个词照用：「复杂结构模式」（界面上既有）、「学习链路」（用户定的名，`LP`）。

### 1.3 窄剖面的准入判据

一个剖面成立 ⇔ 能给出**一句"它不接受什么"**（§4.4），且这句话里的每一条都能落到矩阵的 ✗ 上。三条例外不算成立：

- ❌ **"少画几个按钮"不等于窄**：把全模式的开关摆一屏让人自己关，是把设计责任推给使用者。**窄 = 该模式的实现里没有那个分支**。
- ❌ **"以后可能用得上"不能当理由**：○ 必须写清**什么条件下才开**（§3.4 不变量③），没有条件的 ○ 就是 ✗ 的伪装。
- ❌ **不许靠"关掉可视化"来窄**：被关掉的能力对这份数据意味着什么，必须在图上或状态栏里**看得见**（§6.5）。

## 2. 能力目录（**唯一能力真源**）

> 读法：编号 `C-<组>-<两位序号>`，它**就是引用键**（矩阵、计划、将来的断言名、CHANGELOG 都用它指同一件事；改编号 = 断掉所有引用）。
> 列义：
> - **依赖的数据字段** = 这条能力读/写哪些字段。**都不含节点新增字段**（§6 的禁令）。
> - **判据** = 怎么算"支持了"。写的是**可观测量**（坐标、计数、顺序、opacity、哈希），不是"实现了某某"。
> - **覆盖** = 在几个剖面里出现（含 ○），**权威在 §3.2 矩阵**，本列是它的派生摘要，由 `check-matrix.js` 逐格对拍。
> - **【必备】** 写在「能力」那一格的最前面（例：`| C-F1-05 | **【必备】** 文本永不溢出 | … |`）= 判据必须成立（§1.1）。
>
> 能力条数**不写在正文**：以本节的表行为准。

### 2.1 形状与文本（对应任务书 F1）

> 本组存在的理由：一张图的最小可读单位是"一个框和框里的字"。任务书把"文字永不溢出"列在 F1，而它其实是**正确性**（不是可选项）⇒ 它是【必备】。

| 编号 | 能力 | 依赖的数据字段 | 判据（怎么算"支持了"） | 覆盖 |
|---|---|---|---|---|
| `C-F1-01` | 六种形状几何：`rect` / `round` / `diamond` / `pill` / `cylinder` / `row`，含圆角、描边、填充 | `nodes[].type` `nodes[].style` `nodes[].rect` | 六种各画出一个节点；`diamond` 的四个顶点坐标 = 其 `rect` 四条边的中点（±0.5px）；圆角半径按类型取固定 token | 3/5 |
| `C-F1-02` | 三段式内容：主标题 + 副标题 + 徽标，字号各自独立 | `nodes[].title` `nodes[].subtitle` `nodes[].badge` | 三段的基线 y 互不相等且顺序固定；任一段缺失时其余两段的位置**不变**（不塌陷） | 4/5 |
| `C-F1-03` | 框内自动换行 | 同上 + 框宽 | 超宽文本被切成 ≥2 行；每行 `measuredWidth <= boxWidth - 2*padding`；换行后框高 = 行数 × 行高 + 2*padding | 5/5 |
| `C-F1-04` | 超宽缩字号（下限 8.5px） | 同上 + 字号阶梯 | 字号从 14 逐档下调直到放得下或触到 8.5；触底仍放不下 ⇒ 转 `C-F1-03` 或加宽；**任何情况下字号 ≥ 8.5** | 2/5 |
| `C-F1-05` | **【必备】** 文本永不溢出 | 全部文本字段 + 框几何 | 逐节点：`measuredWidth <= boxWidth - 2*padding` 且 `measuredHeight <= boxHeight - 2*padding`；**溢出计数必须为 0**（导出前与渲染后各判一次） | 5/5 |

### 2.2 容器与背景（对应 F2）

> 本组存在的理由：任务书的两种"分组"是**两件事** —— `containers` 框住一组节点（可移动、可有布局），`layers` 是整幅图的**背景分区**（节点之下、不参与布局）。合成一条能力，就没法只画分区不画框（架构图常见）。

| 编号 | 能力 | 依赖的数据字段 | 判据（怎么算"支持了"） | 覆盖 |
|---|---|---|---|---|
| `C-F2-01` | 容器框（带标题的分组边界） | `containers[].id/label/rect` | 容器框可见且标题在框内；框的 z-order 在层带**之上**、节点**之下** | 3/5 |
| `C-F2-02` | 容器 `layout: stack`（子项纵向等距 + 高度自适应） | `containers[].layout/children[]` | 子项纵向间距两两相等（±0.5px）；容器高 = 子项高之和 + 内边距×2 + 间距之和；子项**不改自己的 `rect`** | 3/5 |
| `C-F2-03` | 容器 `layout: free`（子项用自身坐标） | `containers[].layout` + `nodes[].rect` | 子项坐标逐个等于其声明值；容器高度取子项包围盒 + 内边距 | 3/5 |
| `C-F2-04` | 层带（背景色带，独立 z-index） | `layers[].rect/fill` | 层带矩形在节点**之下**（SVG 里 `g[data-z="layers"]` 早于 `nodes`）；层带之间不重叠 | 2/5 |
| `C-F2-05` | 层带标签（竖排 / 横排） | `layers[].label` + `labelSide` | 标签朝向由数据决定；标签是**文字**不是水印（与 `C-F2-06` 第三档分开） | 2/5 |
| `C-F2-06` | 层带标签避让：预留 gutter → 移到空白区 → 加水印 | `layers[].watermark{text,rotate,opacity}` | 三档按顺序尝试；最终态判据：**标签矩形与所有节点/容器矩形零相交**；落到第三档时 `watermark.opacity < 1` 且记录到 `report.degraded[]` | 2/5 |

### 2.3 连线（对应 F3）

> 本组存在的理由：任务书把"连线"写成一条 F3，但它里面混了**四类完全不同的东西**：锚点（几何入口）、路由（路径形状）、语义（箭头/线型/颜色）、冲突处理（交叉/通道）。四类各自能单独开关 —— 例如逻辑链路要正交 + overpass，而架构图要正交但不一定要 overpass。

| 编号 | 能力 | 依赖的数据字段 | 判据（怎么算"支持了"） | 覆盖 |
|---|---|---|---|---|
| `C-F3-01` | 边端点：节点级锚点 | `edges[].from/to.node` | 端点落在目标节点边界（不是中心）；`from`/`to` 任一指向不存在的节点 ⇒ 校验判红 | 3/5 |
| `C-F3-02` | 端口锚点：`n/s/e/w` 或自定义坐标 | `edges[].from/to.port` + `nodes[].ports{}` | 指定端口时端点 = 该端口坐标（±0.5px）；未指定时走 `C-F3-03` | 3/5 |
| `C-F3-03` | 自动选边（代价最小的边） | 同上 | 对 4 个 n/s/e/w 各算一次走线代价，取最小；**同输入同结果**（代价相等时按 `n<e<s<w` 定序） | 3/5 |
| `C-F3-04` | 路由 `straight` | `edges[].route` | 路径 = 一条线段，无中间折点 | 3/5 |
| `C-F3-05` | 路由 `curve` | `edges[].route` | 路径 = 三次贝塞尔；控制点由两端端口法向导出（无随机） | 3/5 |
| `C-F3-06` | 路由 `orthogonal`（默认） | `edges[].route` + 网格 | 路径所有段与轴平行；折点坐标都是 `grid` 的整数倍；**不与本节点自己的框相交** | 3/5 |
| `C-F3-07` | 箭头（`arrow.end`） | `edges[].arrow.end` | 末端有箭头，箭头尖端 = 路径末点（±0.5px）；起点无箭头 | 3/5 |
| `C-F3-08` | 两端独立箭头（双向） | `edges[].arrow.start` | 两端都有箭头；只开 `start` 时反向箭头成立（判据同 `C-F3-07` 镜像） | 3/5 |
| `C-F3-09` | 扇出 / 汇聚（共享端点的分流与合流） | `edges[]` 的多条共端点 | 同一节点同侧的多条边，端口坐标互不相同且间距 ≥ 8px；扇出/汇聚计数 ≥ 1 的图能画出来不叠线 | 3/5 |
| `C-F3-10` | 自环 | `edges[].from.node == to.node` | 自环路径闭合且**不穿过自己的框**；自环数 ≥ 1 的图能画 | 2/5 |
| `C-F3-11` | 跨层回边（反向 / 跨 rank 边） | `edges[]` + 分层结果 | 反向边存在时布局不报错；回边路径长度 > 同层边，且不穿任何节点 | 3/5 |
| `C-F3-12` | 线型 `solid` / `dashed` / `dotted` | `edges[].style` | 三档的 `stroke-dasharray` 互不相同且为确定值（虚线 `5 4`；点线由 token 定） | 3/5 |
| `C-F3-13` | 边语义色 | `edges[].color` / `edges[].style` | 颜色取自 classDef token（`C-F6-01`），非字面色值直写 | 3/5 |
| `C-F3-14` | 边标签 | `edges[].label` | 标签文字可见；锚点在路径中点附近（±1 个候选位距离） | 3/5 |
| `C-F3-15` | 边标签避让（候选位打分 + 矩形碰撞） | 同上 + 全图矩形 | 标签矩形与**任一**节点/容器/其他标签零相交；候选位按"压线/压框/出界"三项打分，取最高分 | 3/5 |
| `C-F3-16` | 交叉检测与 `crossings` 统计 | 全部路径 | 输出 `crossings` 计数；**该计数必须等于独立 recount 的结果**（不许统计自己给自己打分） | 3/5 |
| `C-F3-17` | 交叉断开 4px | 同上 | 低优先级线在交叉点两侧各断 4px（路径被切成两段，间隙可量） | 3/5 |
| `C-F3-18` | 交叉 overpass（白色描边立交） | 同上 | 交叉点处**高优先级线连续**、低优先级线有 4px 白色描边环绕；断言按交叉点逐点查 | 3/5 |
| `C-F3-19` | 通道 lane 分配（同通道 ≥ 8px） | 同上 | 同一通道内的多条平行线，相邻两条中心距 ≥ 8px；通道数 = 独立 lane 数（无重叠） | 3/5 |

### 2.4 布局（对应 F4）

> 本组存在的理由：任务书 F4 混了**自动布局**（算法）、**手工微调**（人的输入）、**约束工具**（吸附/对齐）三件事。三件事的失败方式完全不同（算法不稳定 / 人被算法覆盖 / 吸附把坐标写成非网格值），合成一条就分不清是哪种坏。

| 编号 | 能力 | 依赖的数据字段 | 判据（怎么算"支持了"） | 覆盖 |
|---|---|---|---|---|
| `C-F4-01` | 分层布局（rank） | `nodes[]` `edges[]` `graph.direction` | 同一 rank 的节点 x（LR 时）相等 ±0.5px；rank 沿边方向单调递增（反向边除外） | 3/5 |
| `C-F4-02` | 主方向 `LR` / `TB` | `graph.direction` | 两档产出的包围盒长宽比按方向翻转；同档内同输入同输出 | 5/5 |
| `C-F4-03` | 间距可调（节点间距 / 层间距） | `graph.gap.node/gap.rank` | 改一个间距值 ⇒ 只有该轴上的间距变化，节点数不变、拓扑不变 | 5/5 |
| `C-F4-04` | **【必备】** 布局输出稳定 | 全部输入 | 同一份 JSON 两次渲染，坐标逐字节相同（序列化后 sha256 相同）；**节点数组顺序打乱后**每节点 rank 与 `crossings` 不变 | 5/5 |
| `C-F4-05` | 手工拖动写回 + `pinned` | `meta.nodeOffsets` + `graph.pinned[]` | 拖动后偏移写进 `meta.nodeOffsets`（相对自动布局位置，±20000 内）；重排后该节点位置不再被覆盖；`pinned` 之外的项目零新增键 | 3/5 |
| `C-F4-06` | 8px 网格吸附 | `graph.grid` | 拖动落点坐标都是 `grid` 的整数倍（±0.001） | 3/5 |
| `C-F4-07` | 对齐 / 等距分布 | 选中集 + `graph.grid` | 对齐后目标轴坐标相等 ±0.5px；等距后相邻间距差 ≤ 0.5px | 3/5 |
| `C-F4-08` | 树形布局（左右分布 / 紧凑树） | `children[]` + `meta.layout` | 深度相同的节点在同一列（±0.5px）；叶子纵向不重叠；两侧分布时左右子树各归一侧 | 3/5 |
| `C-F4-09` | 径向布局 | `children[]` | 同一深度的节点落在同一半径圆上（半径 ±0.5px）；相邻叶节点角距 ≥ 其标签所需角距（否则报"放不下"而不是硬画） | 1/5 |
| `C-F4-10` | 折叠感知布局（只为展开子树定框） | `children[].expanded` | 折叠节点的子节点不占布局空间；展开/折叠后**其余节点坐标按同一规则重算**且稳定 | 3/5 |

### 2.5 文本测量（对应 F5）

### 2.11 算法（对应任务书 §6）

> 本组存在的理由：任务书的"算法要求"是**验收重点**，而它们不是"功能"：`C-A-01`…`C-A-04` 是 Sugiyama 的四步，任一步缺失都能出图但会出**不同的坏图**（成环处抖动 / rank 错 / 交叉多 / 坐标乱）。所以四步分开编号，让"哪一步没做"可判。

| 编号 | 能力 | 依赖的数据字段 | 判据（怎么算"支持了"） | 覆盖 |
|---|---|---|---|---|
| `C-A-01` | 去环（cycle removal） | `edges[]` | 有环输入不报错、不死循环；被反转的边在 `report.reversed[]` 里逐条点名 | 3/5 |
| `C-A-02` | 分层（rank assignment） | `edges[]` | 每节点 rank 可输出；同 rank 无直连边（分层有效性的机械判据） | 3/5 |
| `C-A-03` | 层内排序降交叉 | rank 内序 | 相邻两层两两交换后交叉数不再下降（局部最优的可判形式）；排序结果与输入数组顺序无关 | 3/5 |
| `C-A-04` | 坐标分配 | rank + 序 + 尺寸 | 同 rank 对齐（±0.5px）；**父节点居中于其子节点**：本工程副轴坐标量化到 8px，而子节点中心都在 8 的倍数上 ⇒ k 个子节点中心的均值 = 8·(Σaᵢ)/k，**k ∤ Σaᵢ 时不在网格上**（k=2、a={0,1} ⇒ 均值 4）⇒ "居中"与"坐标落在 8 的网格上"**算术互斥**，误差下界是半个步长。所以判据分三档：①**层内唯一节点**（无次序约束，目标中心本身在网格上）⇒ 误差 **=== 0**；②**兄弟并列**（k 个节点共享同一个父/子，全居中在几何上不可能）⇒ **对称性**：误差两两互为相反数、和的绝对值 ≤ 4；③**全图**：`report.centering[]` 给 `{target, actual, errorPx, exact}` **原值**，`exact` 节点数 ≥ 1 且误差均值 ≤ 4。全图包围盒最小化（无整列空档 > 层间距） | 3/5 |
| `C-A-05` | 网格障碍图上的 A*（代价 = 长度 + 拐弯 + 交叉 + 贴边） | 节点矩形 + 网格 | 四项代价都是**可读出的数**（`report.cost` 分解）；调高拐弯惩罚 ⇒ 折点数不增；路径 0 次穿越节点矩形 | 3/5 |
| `C-A-06` | 矩形碰撞 / 重叠检测（节点重叠、边穿框、标签压框） | 全图矩形 | 三类冲突各能被独立数出来（三个计数分开，不合并成一个"有冲突"）；冲突 0 时计数 = 0 | 3/5 |
| `C-A-07` | 几何自检闭环（≤3 轮 + `report`） | 上述全部 | 渲染 → 查 `C-A-06` 三类冲突 + 溢出 + 孤立节点 → 调整 → 重渲；轮数 ≤ 3；`report` 含 `problems[]` / `actions[]` / `degraded[]`，且**每次调整都能指到一条具体问题** | 4/5 |

### 3.3 每个剖面"它不接受什么"（✗ 的逐条理由）

> 规则：本节每一行用**编号区间**覆盖矩阵里该剖面的**每一个 ✗**，一个不漏 —— `check-matrix.js` 会按区间展开逐格核对（缺一格就 exit 1）。

### 3.4 三条不变量（这一节是 `check-matrix.js` 判的东西）

> 三条都是**机械可判**的，所以它们才算判据；判不了的（"理由写得好不好"）写在下面"能力边界"里，不当判过。

| # | 不变量 | 判红条件 | 为什么它是判据 |
|---|---|---|---|
| ① | **`complex` 列零 ✗** | 该列出现任何 ✗ | D1 的可判形式："支持全部功能" = 没有任何一条在这列被关掉 |
| ② | **【必备】行全 ✓** | 某个 【必备】能力在任一剖面不是 ✓ | 必备是正确性（不是可选项）：换个实现可以，**没有判据不行** |
| ③ | **每个 ✗ / ○ 都有出处** | 某格是 ✗ 但 §3.3 该剖面的区间没覆盖它；或某格是 ○ 但 §3.5 没给"什么条件下才开" | 没有理由的 ✗ = 悄悄少做一件事；没有条件的 ○ = ✗ 的伪装 |

**怎么跑**：`node .review/20261051-图能力模式体系/check-matrix.js` ⇒ exit 0 才是三条全过。
⚠️ **那个探针是工作产物**（在 `.review/`，可整目录删）。它删了**不影响这三条判据**：判据的定义就在上面那张表里，删了它就按表人工核一遍（几十行，能核）。探针的价值只是"把人工核变成一条命令"，不是"没有它就没有判据"。
**能力边界（三档，照 `docs/RULES.md` 的口径写清）**：
- **判红**：上面三条 + 矩阵编号与 §2 表编号不一致（少一条 / 多一条 / 拼错）+ §2 的「覆盖」列与矩阵逐格不符 + 本文章节编号断号。
- **只报告**：某剖面的 ✓ 总数（读数是给人看的，不设阈值）。
- **跳过**：理由写得对不对、够不够具体 —— 那要读语义，本探针**不判**（人工残差，靠改矩阵的人顺手写）。

| 面 | 由谁决定 | 剖面之间是否相同 | 这条决定了什么 |
|---|---|---|---|
| **数据面**（`format` / `meta` / `data` / `assoc` / `bindings` / `graph`） | 数据契约（`docs/DATA-FORMAT.md` / `docs/ITEM-MODEL.md`） | **完全相同** | **同一个项目能被任意剖面打开**（§6） |
| 布局面（用哪个布局算法、什么方向、什么间距） | 剖面 | 不同 | 同一份数据在不同剖面里**长得不一样**，但内容一样 |
| 交互面（能做什么动作） | 剖面 | 不同 | 控件集合 = 剖面展开集合（§4.3） |
| 导出面（能导出什么） | 剖面 | 不同 | 导出是"交付方式"，不是数据能力 |
| 样式面（token 与语义色） | 剖面 + 主题 | 部分不同 | 语义 classDef 只在有语义角色的剖面出现 |
| **取值收窄**面 | 剖面 | 不同 | 同一条能力，在不同剖面里**可用取值**不同（§4.2） |

### 4.2 取值收窄 ≠ 关能力

有些差别**不足以**关掉一条能力，只够收窄它的取值。这类差别必须写成"取值收窄"，否则矩阵会为了表达它而制造一堆假 ✗：

| 能力 | 收窄方式 | 例 |
|---|---|---|
| `C-F1-01` 六形状 | 只暴露其中几型 | `logic` 只给 `rect` / `round` / `diamond`（环节 / 起止 / 判断），其余三型不给 |
| `C-F4-02` 主方向 | 取值语义不同 | `mindmap` 的"方向"是**左右分侧**（今天 jsMind 只认 root 直接子节点的 `direction`），与 `complex` 的 `LR/TB` 不是同一件事 —— 所以这一格两边都 ✓，但**取值表不同** |
| `C-F2-06` 层带标签避让 | 档数不同 | `module` 三档全给；其它有层带的剖面只给第一档（预留 gutter），因为水印是"实在放不下"的兜底 |
| `C-F6-01` 语义 classDef | 取值子集 | `logic` 只用"主路径 / 分支 / 桥接"三类；`module` 用全十类 |

#### 4.2.1 形状收窄落地在哪（`C-F1-01`，收口批 · 甲）

> 这一小节回答四个问题：**规则在哪、表长什么样、越界了怎么处置、界面上为什么还是六型。**

**① 规则只有一份**：`src/diagram/profiles.js` 的 `SHAPES_BY_PROFILE`（`shapesFor(profile)` 出允许集，
`narrowShape(profile, type)` 出"从什么换到什么"）。表按剖面给全，不替用户发明规则：

| 剖面 | 允许的画法形状 | 依据 |
|---|---|---|
| `complex` | 六型全给 | §3.4 不变量①：全开剖面零 ✗ |
| `module` | 六型全给 | §4.2 只收窄 `logic`；`module` 没有收窄的设计依据 ⇒ **不收**（不许替用户发明规则） |
| `logic` | `rect` / `round` / `diamond` | 本表第一行（环节 / 起止 / 判断） |
| `mindmap` / `path` | **空集** | 这两档把 `C-F1-01` 判 ✗（§3.2）⇒ 形状这条能力**不出现**，那不是"收窄"，内核遇到要**拒绝** |

降级映射（只 `logic` 用得上，每条都给理由）：`cylinder→round`（`logic` 里它扮演"起止"，没有"存储"这个语义）、
`row→rect`（条目层在 `logic` 列是 ✗，行卡本就该退回普通环节框）、`pill→round`（标签在 `logic` 列是 ✗，
圆角在 `round` 上还在）。

**② 越界了怎么处置**（`opts.shapePolicy`，三档，**都不许静默**）：

| 档 | 行为 | 给谁用 |
|---|---|---|
| `report`（**缺省**） | 画法**不动**，但每个越界节点逐条写进 `report.profileShapes.outOfProfile[]` 与 `report.degraded[]`（`W_SHAPE_OUT_OF_PROFILE`） | 画布（见 ③）与"先保持现状、只求可判"的调用方 |
| `degrade` | 按上面的映射换画法，逐条点名 `W_SHAPE_NARROWED` | 要"图上立刻只出现该剖面允许的形状"的调用方 |
| `reject` | 抛 `E_PROFILE_SHAPE`，带 `detail.object{node,type,profile}` / `detail.allowed` / `detail.fixes[]` | 导出门禁、AI 生成前的自检 |

剖面把 `C-F1-01` 判 ✗（`mindmap` / `path`）⇒ **无论哪一档都抛 `E_PROFILE_SHAPE`**：那是"这个剖面没有形状这条能力"，
降级到某个形状等于把关掉的能力画出来。

**③ 界面上为什么还是六型（如实登记，别当成"已收窄"）**：画布的派生 `renderer/app-core.js` 的 `diagramNodeOf()`
把根画成 `cylinder`、条目节点画成 `row`、带标签的节点画成 `pill` ⇒ 它派生的 doc 在 `logic` 剖面下**必然越界**。
缺省档因此选 `report`（登记不改画法）。**实测读数**（`SMOKE_ONLY=59`，同一份夹具）：

- 缺省 `report`：`logic` 形状 = `cylinder/diamond/pill/rect/round/row`、`path=2` ⇒ **六型都在**；
- 改成 `degrade`：`logic` 形状 = `diamond/rect/round`、`path=0` ⇒ **域 59 甲的"六种形状各至少一个"当场红**
  （报文：`✗ logic 的 SVG 里没有 path ｜ logic 缺这几种形状：["cylinder","pill","row"]`）。

⇒ 两条判据（§4.2 的形状收窄 vs 域 59 甲的"六形状"）**在画布上互斥**，不是实现问题。要收窄到三型必须同批改域 59 甲的验收口径
（把"六种形状各至少一个"改成"每种形状 ⊆ 该剖面允许集，且允许集内每种至少出现一次"）——
**那一步在 `scripts/smoke/**`（本批边界外）**，所以缺省停在 `report`：规则、三档处置、稳定码与逐节点点名都在，
**接线（`app-core.js` 的派生 + 域 59 的口径）一步没做**，做的时候不需要再设计一遍。

### 4.3 控件面的判据（"提高易用性"的可判形式）

> 一句话：**该模式的界面与命令里不出现它不需要的控件与参数。**

三条落地要求（缺一条这句话就成口号）：

1. **控件必须声明"我是哪条能力"**：每个控件带 `data-cap="C-F3-06"`（或命令选项在 `cli/registry.js` 的 `options` 旁边声明所属能力）。没有归属的控件 = 不受剖面管 = 一定会漏。
2. **控件集合由剖面生成，不许手写条件分支**：渲染时按 profile 展开集合 `filter` 一次，**不许**在 N 个地方写 `if (mode === 'complex')`。判据：源码里"模式名出现在条件里"的处数 = 0（只允许出现在 profile 定义与派发处各一处）。
3. **判据可执行**：切到某剖面后，`[data-cap]` 的集合**逐条等于**该 profile 展开集合（双向：多一个、少一个都判红）。五个剖面各跑一次。

### 4.4 五个剖面的一句话定义

- `complex`：**不接受"某条能力缺失"** —— 它是唯一全开剖面；它只能靠**取值收窄**变简单，不许关能力。
- `mindmap`：**不接受"图"这件事** —— 没有层带、没有容器、没有任意边、没有端口、没有自由坐标、没有条目卡片；只认**一棵有序树 + 折叠 + 主题 + 导出**。
- `path`：**不接受"位置自由"** —— 位置一律由布局给；顺序的唯一真源是 `children` 数组序；只认**固定顺序的树 + 折叠 + 标题 + 条目卡片**。
- `logic`：**不接受"分区"** —— 层是拓扑产物（rank），不是手工画的背景带；只认**有向图 + 正交布线 + 路径高亮**。
- `module`：**不接受"逐条内容"** —— 节点讲"这个模块是什么"，不讲"它的每一条知识"；只认**分层分区 + 容器 + 正交布线 + 语义色**。

## 5. 与 jsMind 的关系（结论先给）

### 5.1 结论：**并存 —— 窄剖面继续用 jsMind，全模式新建独立 SVG 渲染器，同一份 JSON，一个剖面开关**

| 剖面 | 渲染器 | 为什么 |
|---|---|---|
| `mindmap` / `path` | **jsMind 0.9.1（不动）** | 它们要的恰好是 jsMind 最强的那一半：有序树、折叠、左右分侧、编辑入口、缩放平移 |
| `complex` / `logic` / `module` | **新建 SVG 渲染器**（`renderer/diagram/`，分层 model → measure → layout → route → paint → export） | 它们要的（任意边、端口、层带、容器、正交布线、通道、overpass）**jsMind 的数据模型里根本没有位置** |

**三条纪律**（并存最容易出的三种坏结果，各一条）：

1. **一份数据，两套视图**：不许为全模式另存一份项目文件，也不许"导出/导入"在两套之间搬。
2. **窄剖面不许把结构写进节点**（§6 的禁令）：`serializeTree` 是手挑字段白名单，写进去会被静默抹掉。
3. **两套渲染器不共享"半成品"**：布局、测量、导出各自成模块，宁可重复一点，也不许抽一个"两边都要适配"的中间层（那会把 jsMind 的内部符号渗进新渲染器）。

### 5.2 为什么不是"替换掉 jsMind"

- **它今天承担的是整个主窗交互**：树的画法、折叠、缩放平移、选中、拖动改序、编辑入口（`MM.Editor.create(host)`）、详情框锚点……替换 = 把这些**逐条重做并逐条重新验证**，而收益为零（这些剖面本来就够用）。
- **我们已经主动接管了它的一部分内部**（清单在 `renderer/vendor/JSMIND-INTERNALS.md`，升级前要人工回归）—— 替换等于把那批接管成果作废，同时把"升级要读的清单"换成一份"新渲染器必须自证"的清单，成本只增不减。
- **它的数据模型只认 5 个字段**：`id` / `topic` / `children` / `direction` / `expanded`（`renderer/draft-map.js` 的注释写明：`_extract_data` 只排掉这五个，其余原样进 `node.data`）。这不是"缺几个功能"，是**缺一整层几何**（见 §5.3）。

### 5.3 为什么不是"把全模式也塞进 jsMind"

- **塞不进去的是几何**：层带（背景分区）、容器（分组框）、端口锚点、正交路径、通道、overpass —— jsMind 的坐标系里没有"边"，只有父子连线。
- **能塞进去的只有"卡片"**：节点内容走 `innerHTML`，所以可以把条目/表格塞进**一个节点**里。但那画出来的是"节点内部"，不是"图"。用它冒充全模式，等于把"能画"当成"能表达"（`.review/20261050-复杂结构展示/对比.md` 的结论正是这一句）。
- **而且它会撞 §6**：要把结构塞进节点，只能走 `node.data` —— 那正是 `serializeTree` 会静默抹掉、`validate` 又不管的那一格。

### 5.4 并存的代价，与"什么时候该收敛回去"

**代价（如实）**：两套交互、两套导出、两套冒烟域；同一个"折叠"在两套里各有一份实现；新人要读两个入口。

**收敛判据（升级触发条件，不是欠账）**：同时满足三条时，才重新评估"把 `mindmap` / `path` 也切到新渲染器、删掉 jsMind"：

1. 新渲染器已经能画 `mindmap` / `path` 要的全部：树形布局、折叠、左右分侧、缩放平移、编辑入口；
2. 有冒烟域把主窗的那批交互逐条压住（不是"能用"，是逐条断言）；
3. 实测回归成本低于并存成本（给出改前/改后的读数）。

未满足 ⇒ **保持并存**，且这不记为欠账（有据降级，理由在 §5.2/§5.3）。

## 6. 数据模型落点（"同一个项目能不能同时被窄模式和全模式打开"）

### 6.1 结论

**能，而且必须能。** 做法：**顶层加一个可选的 `graph` 附加层，节点字段一个都不加**；位置类信息继续用**既有**的 `meta.nodeOffsets`（相对自动布局的偏移）。于是：

- 窄剖面（jsMind）看到的仍然是一棵纯树 —— 它今天就已经在用 `meta.nodeOffsets` 画树偏移，**坐标不会分裂成两套**；
- 全剖面（新渲染器）多读一个 `graph`，缺省 = 无附加结构；
- **同一个项目名、同一份 JSON**，由剖面开关决定怎么画。

### 6.2 为什么不能写在节点上（两条实测 + 一次先例）

| 事实 | 怎么来的 | 后果 |
|---|---|---|
| `validate` 对**未知顶层键**与**未知节点字段**都**静默通过**（两档 exit 0） | `node .review/20261051-图能力模式体系/probe-graph-keys.js`（基线绿 → 加 `graph` 键仍绿 → 加节点字段 `rect` 仍绿） | "校验通过"**不能**证明"这个字段被支持"；把数据放在没人校验的地方，等于没有契约 |
| `renderer/app-core.js` 的 `serializeTree` 是**手挑字段白名单**（`id/topic/expanded/detail/tags/images/files/links/background/localPath/qa/origin/items/detailMode`） | 读源码 | 节点上多出来的任何字段，**界面下一次保存就消失**；该文件里已记录 `qa` / `localPath` / `origin` / `items` 四次同型事故 |
| 位置类信息已经有既有的家：`meta.themeOffsets` / `meta.nodeOffsets`（相对偏移、缺省 = 未偏移、±20000 上下界、`formatVersion` 不升、非空才写） | `src/schema.js` 的 `validateOffsetMap` 与 `docs/DATA-FORMAT.md` §1 | 全模式的"人工微调"**没有理由**新造一套坐标 |

⇒ **禁令（写进实现批的禁区清单）**：不许为了"让 jsMind 也能显示"而往节点上写 `rect` / `pinned` / `layers` / `edges`；也不许往 `node.data` 里塞结构。这条不是洁癖：它是"静默数据丢失"的唯一入口。

### 6.3 `graph` 的形状（**草案**，不是契约定稿）

```jsonc
"graph": {
  "version": 1,                    // 自带版本（≠ meta.formatVersion：那一个动不得，见 §6.4）
  "profile": "complex",            // 这份图默认用哪个剖面打开（人可切）
  "direction": "LR",               // LR | TB
  "grid": 8,
  "layers":     [ { "id": "...", "label": "...", "rect": [x,y,w,h], "fill": "...", "watermark": { "text": "...", "rotate": -90, "opacity": 0.5 } } ],
  "containers": [ { "id": "...", "label": "...", "rect": [x,y,w,h], "layout": "stack", "children": ["<nodeId>"] } ],
  "edges":      [ { "id": "...", "from": { "node": "...", "port": "e" }, "to": { "node": "...", "port": "w" },
                    "route": "orthogonal", "style": "dashed", "color": "blue",
                    "arrow": { "start": false, "end": true }, "label": "...", "crossing": "overpass" } ],
  "annotations": [ { "text": "...", "at": [x,y], "style": "note-blue" } ],
  "pinned": ["<nodeId>"]           // 重排时不许覆盖其偏移的节点（偏移本身仍在 meta.nodeOffsets）
}
```

- **不含节点坐标**：坐标 = 自动布局 ⊕ `meta.nodeOffsets`。`pinned` 只表达"别覆盖"，不表达"在哪"。
- **引用只按 id**：`containers[].children[]` / `edges[].from.node` / `pinned[]` 都是节点 id。与 `links[]` 的悬挂检测**同型**：指向不存在的节点 ⇒ `validate` 判红（这条校验是 MS1 的第一件事，见 §7.2）。

### 6.4 四条落地纪律

1. **`validate` 必须同批认识 `graph`**：今天的未知键静默通过（§6.2 实测）⇒ 不加校验就等于"结构在无校验下进盘"。形状校验按 `layers/containers/edges/annotations/pinned` 逐个字段判，引用存在性单独判（悬挂 id 判红）。
2. **`project:save` 必须"载荷没带就从磁盘取回"**：照 `assoc` 的既有做法。不这么做，窄剖面保存一次（整树写回）就会**抹掉整张图** —— 而 `assoc` 当初正是为这件事加的这条规则（`docs/ARCHITECTURE.md` §2.1）。
3. **缺省 = 无附加结构，`formatVersion` 不升**：照 `meta.nodeOffsets` 的先例（缺省 = 未偏移、老项目零迁移、非空才写）。**不要**为 `graph` 加一个迁移命令（那会在"用户什么都没做"的数据里凭空多出一个键）。
4. **版本号放 `graph.version`，不动 `meta.formatVersion`**：后者是 v2/v3 的分界（`src/schema.js` 只接受 2 或 3），动它会让另一半数据"连读都读不了"，把回退路堵死。

### 6.5 三档判据（"同一项目能被两种模式打开"怎么验）

| # | 场景 | 判据（可执行） |
|---|---|---|
| ① | **窄剖面打开带 `graph` 的项目** | 不报错；**序列化产物与磁盘逐字节相同**（零写入）；界面**可见地说明**"本项目含 N 条层带 / M 条边，当前模式不显示"，并给"切到全模式"的入口 |
| ② | **全剖面打开没有 `graph` 的纯树项目** | 按剖面生成**派生布局**，**不写盘**（`isDirty` 仍 false，sha256 不变），直到人显式保存 |
| ③ | **两剖面交替打开同一个项目** | `meta.nodeOffsets` 是**共用的**：窄剖面拖过树、全剖面再打开，偏移仍在；反向亦然（不许出现两套坐标） |

### 6.6 将来怎么扩 `docs/DATA-FORMAT.md`（**本批不改**，只写将来怎么改）

- 新增**一节**（不是往节点字段表里塞行）：`graph` 是**项目级可选对象**，与 `bindings` / `meta.nodeOffsets` 同族。
- 契约表补**一行**（`| graph | object | - | 不出现 | … |`）—— 因为 `scripts/docs-registry-check.js` 的契约覆盖判定按**表行第一列**判（那是 G8 的第 ⑪ 条），散文里写不算。
- **节点字段表一个字节都不动**：这是"同一项目能被多剖面打开"的前提，也是本轮唯一不许让的地方。
- 改契约的批次要同时改 `SCHEMA_FIELDS`（那张清单在门禁脚本里，加一条 `['graph', true, 'DATA-FORMAT']` 才有人判它）。

### 7.2 每一步：范围 / 判据 / 不动什么

#### MS1 渲染内核（`complex` 剖面的子集：手工 JSON → SVG，**不接界面**）

- **范围**：新建 `renderer/diagram/`（`model` / `measure` / `layout` / `paint` / `export` 五个模块起步）；一份**手写 fixture**（取任务书 §3 的 netfilter 图，落成 JSON）；一个 headless 入口（测试直接驱动，不经主窗）。
- **判据**（每条都能跑）：
  - `C-F1-01` 六形状各画出 1 个节点，`diamond` 顶点 = `rect` 四边中点（±0.5px）；
  - `C-F1-05` 溢出计数 = **0**（渲染后一次 + 导出前一次）；
  - **z-order**：SVG 里 `g[data-z]` 的顺序逐字 = `layers, containers, nodes, edges, labels, annotations`（Golden Sample 的"层带标签不被遮挡"从这里开始）；
  - `C-F4-04` / `C-F9-02`：同输入两次渲染，坐标与 SVG 都**逐字节相同**；
  - `C-F8-01`：导出的 SVG 里 0 个外链（`http(s)://` / `url(` 外链 / `@import`）；
  - `C-I-04`：fixture 里条目化节点的 `detail` 与 `renderDetail(items)` 逐字节相等（**渲染不许碰数据**）。
- **不动什么**：`renderer/vendor/**`、既有 `renderer/app-*.js`（一行都不改）、`renderer/index.html`（MS1 不接界面 ⇒ 不加 `<script>`）、`cli/**`、`src/schema.js`（MS1 不写盘）、`projects/**`。
- **依赖**：无。

#### MS2 布局与布线（判据最重的一步）

- **范围**：`C-A-01`…`C-A-04`（Sugiyama 四步）+ `C-A-05`（A*）+ `C-F3-19`（lane）+ `C-F3-14`…`C-F3-18`（标签避让 / 交叉检测 / 断开 / overpass）+ `C-A-06`（碰撞检测）+ `C-A-07` 的几何那半。
- **判据**（Golden Sample 的四条硬指标 + 一条稳定性）：
  - **边穿框 = 0**（逐边 × 逐节点矩形相交；父子边（容器内 stack 子项）的豁免要**写明并单独计数**）；
  - **非预期交叉 ≤ 3，且每一处都必须是 overpass**（逐交叉点断言处理手法）；
  - `crossings` 统计 == **独立 recount** 的结果（不许统计自己给自己打分）；
  - 同通道相邻线中心距 **≥ 8px**；
  - **稳定性**：同输入两跑坐标逐字节相同；**节点数组顺序打乱后**每节点 rank 与 `crossings` 不变。
- **不动什么**：`src/item-model.js` 与 `docs/ITEM-MODEL.md`（契约已冻结）；jsMind 侧一切；不写盘。
- **依赖**：MS1。

#### MS3 交互 + 导出 + 主题

- **范围**：`C-F7-01`…`C-F7-05`、`C-F6-01`…`C-F6-04`、`C-F8-01`…`C-F8-04`。
- **判据**：

  - 路径高亮：其余元素 opacity **= 0.10**（精确两位）；

  - 主题切换后 `C-F1-05` 仍 0 溢出（深色 token 的字重/字号若变，重排必须跟上）。

#### MS4 数据落点 + 剖面开关 + AI 生成层

- **范围**：`graph` 的校验与水合（§6.3/§6.4）；`project:save` 的"未带即取回"；五个剖面的 profile 定义与控件面生成（§4.3）；`C-G-01`…`C-G-05`；`C-F9-03` patch。
- **判据**：
  - `graph` 里悬挂 nodeId ⇒ `validate` **判红并点名**（判别力：故意删一个被引用的节点，必须红）；
  - 窄剖面保存一次后，磁盘上的 `graph` **逐字节不变**（= §6.5 判据①）；
  - 五个剖面各跑一次控件面：`[data-cap]` 集合与 profile 展开集合**双向相等**；
  - AI 输出过**双层校验**（结构：`validate` 绿；几何：溢出/重叠/穿框/孤立四类计数），≤ 3 轮，`report` 含 `problems[] / actions[] / degraded[]`；

- **不动什么**：不许把结构写进节点（§6.2 禁令）；不改 `docs/ITEM-MODEL.md` 契约；不改 jsMind。
- **依赖**：MS1–MS3。

| **时序图剖面** | ① 它的几何是"生命线 + 消息时间轴"，与"分层 + 网格障碍 A*"是两套坐标系统，塞进同一渲染器会让 MS2 的判据（穿框/交叉）变得不适用；② 用户原话点名的例子是"现在的思维导图的模式"，没有时序 ⇒ 无据不做（`docs/RULES.md` M1） | 用户给出**一个真实需求样本**（哪份文档、要看什么），并说明为什么逻辑链路剖面画不了 |
| **状态机剖面** | 它就是"有向图 + 自环 + 边标签" ⇒ **逻辑链路剖面已经能画**，单独立剖面只多一套取值收窄与一套控件面，收益为负 | 出现"状态机专属"的需求（如状态覆盖率的可视化），且逻辑链路剖面的判据表达不了 |
| **泳道图 / 时间轴 / 多页编排 / 边上折点手工编辑** | 任务书自己把它们列在 P1；各自要新的数据字段与新的判据（折点编辑尤其：它会让 `C-F9-02` 的"同输入同输出"多一层输入） | 任务书 P1 的原话被用户重新提出，且各给一份真实样本 |
| **主题市场 / 图标库（AWS/Azure/K8s）** | 与 `docs/ROADMAP.md`「已否决」的定位冲突（单机、AI 驱动迭代）—— 那里是唯一权威，此处只引用不复述 | 见 `docs/ROADMAP.md`「已否决」 |
| **两套渲染器同时并排显示同一个项目** | 两套交互同时挂一棵树，性能与"哪个在写盘"都会失控；分屏需求尚未出现 | 用户明确要"左边窄模式、右边全模式"对照看 |

## 10. 参考采纳（archify / graphify → 本工程能力）

> 这一节只回答一件事：**两个外部工程里，哪些做法被我们采纳了、落到哪条 `C-*`、哪些没采纳以及为什么**。
> 逐条清单（含"散文来源"标注与父批前提核对）在 `.review/20261061-参考archify与graphify/提取.md`；
> 那一个是**工作产物**（可整目录删），本节是**留下来的结论**。
>
> ⚠️ 前提：**archify 明确不做通用自动布局**（其 README 的"Layout judgment over generic auto-layout"与
> "general-purpose auto-layout … intentionally outside the current scope"）—— 它是"Agent 读仓库、自己给坐标、
> CLI 判一遍"，我们是"用户的笔记图谱、必须自动排"。所以凡采纳的都是**判据/校验思路**，不是它的放置策略。

### 10.1 采纳（改造后采纳的也列在这里）

| 参考做法 | 落到哪 | 怎么落地（与它的差别） |
|---|---|---|
| 交付前**原子自检**（渲染 → 全门禁 → 收据；失败保留旧产物） | `C-F5-04` / `C-F8-01` | 只做**纯的那半**：`exportOf()` 返回 `{ok, bytes, checks, problems}`，不过就不交产物；**原子落盘在 CLI 层**（本批不许改 `cli/**`）⇒ 缺口 |
| **Clean Flow**：连线不许穿过无关节点框，端点豁免 | 判据 1（`C-A-06`） | 已有（MS2 的"穿框 = 0"）；本批只把它写进对照表，没动判据 |
| **同一 lane 重叠 ≥8px 会被读成合并/分支** | `C-F3-19` | 已有 `LANE_GAP=8` + `report.routing.overlaps` 读数 |
| **标签到别的路径的净空 4px** | `C-F3-15` | 已有 `LABEL_PATH_CLEARANCE=4` 且判据就是 4px（**两边撞上同一个数**，是独立证据） |
| **布局意图优先于自动布局** | `C-F4-05` | 已有 `graph.pinned[]`；本批补它漏掉的另一半：**钉住的框与自动区域的重叠避免**（`report.pinnedAvoid[]` 点名谁被推、往哪个轴、推多少） |
| **容器/框架的"走廊"语义**：可垂直穿过、可在顶点相触、不许沿边框共线跑 | `C-F2-01` | **本批定案并落地**：容器**不参与避障**（`blocked` 里只有节点），但沿边框共线跑（重叠 >1px）⇒ `E_ROUTE_ON_BORDER` 读数点名 |
| **同侧端点确定性展开** | `C-F3-09` | 已有（`FANOUT_GAP=16`，按另一端位置排序） |
| **双主题 + 导出内联** | `C-F6-02`…`04` | 本批落地：浅/深两套 token（键集逐键相同、对比度 ≥4.5:1 **现算**）、十个语义 classDef、导出 0 外链 |
| **结构化纯函数流水线 + 每模块一个测试文件** | 架构口径 | 本批新增的 `profiles.js` / `export-svg.js` 都是纯函数模块，各带 `tests/*.test.js` |
| **置信度三档（EXTRACTED / INFERRED / AMBIGUOUS）+ 不确定也要标出来** | `C-G-05` | 只落**纯映射**（语义 → `dashed` + `note`）的契约位置：`edges[].note` **本批不加**（`EDGE_FIELDS` 是封闭表，加字段要同批登记 `SCHEMA_FIELDS`）|
| **"绝不隐藏数字"**（cohesion 给原值） | 全部报告读数 | 本批同样：居中给 `errorPx` 原值、曲线给控制点原值、缺口给 px 原值 |

### 10.2 不采纳（每条一句"为什么"）

| 参考做法 | 为什么不采纳 |
|---|---|
| **图形社区检测 / god nodes / surprising connections**（graphify 的语义层） | 它回答的是"这堆文件里哪些概念连在一起"，而我们的节点是**用户自己写的笔记**（谁连着谁是我们画的图已有的信息）—— 在一张已知拓扑的图上再猜"社区"，产出的不是洞见而是噪音；且 §2 的 76 条能力里没有对应行，**收编它要改 §2/§3.2/§3.3/§3.5 四处**，属设计批 |
| **GraphML / Cypher / Obsidian vault 导出** | §2.8 的导出面只有 SVG / PNG / PDF / 片段四档；前两者是"给图数据库吃"的格式，我们的下游是文档与人，不是 Neo4j |
| **查询结果写回图**（`save_query_result`：把答案变成新节点） | 那是"用图谱自增长"的产品机制（对应 `C-G-03`/`C-G-04` 的 AI 生成层），不是画图能力；写回还会动数据契约（`items`/`detail` 的往返不变式 `C-I-04` 要重审） |
| **两档质量剖面**（`standard` / `showcase`，同一能力两种严格度） | 本文的"剖面"是**功能集合**（§1.2）。两套"profile"同词异义会把 §4.3「控件集合 = 剖面展开集合」这条判据搅浑 |
| **折点/转折段长度阈值**（段 <8px、内部转折 <16px 判短） | 我们已有"折点是 grid 的整数倍"（8px 的整数倍 ⇒ 段长天然 ≥8）；再接"内部转折 ≥16px"会把 A* 用 8px 折弯换更少交叉的**有据取舍**判红 |
| **双候选路由**（H-V-H 主选 + 越障时试 V-H-V） | 我们的 A* 是**全局网格搜索**（候选 = 所有走廊），比"两候选择一"强；补它等于把 A* 降级 |
| **`<title>/<desc>` 无障碍标注** | 会改 MS1 的逐字节基线；无障碍不是本批判据（要有它得单独立批并重录基线） |
| **`sanitize_label` 的"截断到 256 字符"** | 与本工程的「文本永不溢出」冲突：我们是**报错**（`E_TEXT_OVERFLOW`）。静默截断会把"放不下"变成"内容悄悄少了"——本工程有过四次同型事故 |

### 10.3 缺口登记（做不到的，写清缺什么）

| 能力 | 状态 | 缺什么 |
|---|---|---|
| `C-F8-02` PNG（2x/4x） | **未做** | 仓里依赖只有 `electron` / `jsmind` / `vitest` / `pdfjs-dist`（PDF **解析**器）/ `@napi-rs/system-ocr`，**没有任何光栅器**（无 `canvas` / `sharp` / `@resvg/resvg-js` / `pureimage`）。纯 JS 自写光栅化的硬点是**字形**（没有字体轮廓解析就没有文字）；禁 `npm install` ⇒ 不做，也不输出坏图 |
| `C-F8-03` PDF | **未做** | 同上 + 判据要求"文字可提取" ⇒ 中文必须嵌 CID 字体子集 ⇒ 仍需字体解析；§9 第 3 条也已裁定本期不做 |
| 原子落盘（导出） | **未做** | 落盘在 `cli/**`，本批边界外；`src/diagram/**` 零 I/O。只交付"纯的那半"（bytes + 自检 + 可复算） |
| `edges[].note` | **未做** | 改数据契约要同批登记 `SCHEMA_FIELDS`（`scripts/**` 不在本批范围） |

**"做不到"是写在代码里的，不是只写在文档里**：`exportCapabilities()` 里 `png.ok === false` / `pdf.ok === false` 且带 `needs[]` 与 `reason`；
`tests/diagram-theme-export.test.js` 有一条**反向判据**：谁把它改成 `ok: true` 而没实现 ⇒ 那条用例必红。
