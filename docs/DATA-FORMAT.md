## 1. 总体结构

```json
{
  "meta": {
    "name": "项目显示名",
    "author": "",
    "version": "<写入时的应用版本，见 package.json>",
    "formatVersion": 2,
    "rootMode": "themes"
  },
  "format": "node_tree",
  "data": { "id": "root", "topic": "根标题", "expanded": true, "children": [] },
  "assoc": [
    { "id": "a-xxx", "title": "两者之间是什么关系", "members": [
      { "project": "本项目", "id": "node-a" }, { "project": "本项目", "id": "node-b" }
    ], "note": "<p>关联知识（HTML，同 detail 约定）</p>" }
  ]
}
```

`assoc` 是**项目级可选集合**（与 `data` 平级，**不在节点树里**），见 §2.6。

`bindings` 也是**项目级可选集合**（同上：与 `data` 平级、**不在节点树里**），见 §1.5。

### 1.5 bindings：工作区文件夹绑定（可选；缺省 = 未绑定）

> 一句话：**这个项目盯着本机的哪个文件夹**，以及"同步进来时按什么规则转"。
> 用户视角：挑一个文件夹绑定给某个项目 ⇒ 之后那个文件夹里的内容（新增/修改）会被**定时或有变化时**
> 同步进思维导图（**零 token**：纯本地文件事件 + 字符串处理，不经 LLM）。

```json
{
  "bindings": [
    {
      "id": "wb-1",
      "dir": "D:\\notes\\网络笔记",
      "mode": "flat",
      "include": ["*.md"],
      "ignore": ["node_modules", ".git", ".review"],
      "deletions": "propose-only",
      "debounceMs": 800,
      "status": "watching",
      "lastSyncAt": "2026-10-13T12:03:44.101Z"
    }
  ]
}
```

| 字段 | 必填 | 说明 |
|------|------|------|
| id | ✓ | 绑定 id（小写字母/数字/连字符）。**项目内必须唯一** —— 旁路快照按它分文件（见下） |
| dir | ✓ | 本机目录的**绝对路径**。它是本文档「禁止绝对路径」的**明文例外**（与节点 `localPath` 同档，见 §2.5）：绑定天生是机器本地的事实，没有可移植含义。**只校验形状**（非空/无换行/≤500 字符），**不校验目录在不在、读不读得了** —— 那是环境问题，不是数据问题 |
| mode | - | `flat`（缺省）= 目录里的文件**平铺**挂到根节点下；`mirror` = 目录结构与文件夹**同构**（每一级子目录一个容器节点，规则同 `import-dir`）。取别的值**判红** |
| include | - | 文件名/路径通配数组（`*.md` / `assets/*` / `note.md`，大小写不敏感、按路径或文件名匹配）。**缺省 = 全收**（默认范围由绑定自动导入的扩展名集合决定：`.md/.txt/.docx/.pdf`） |
| ignore | - | 忽略通配数组（**按路径段**匹配，`node_modules` 既挡根下那个也挡嵌套的）。`cli` 建绑定时缺省给 `node_modules` / `.git` / `.review` 三项。注意：隐藏项（`.` 开头）、符号链接、依赖目录本来就会被导入走查规则跳过（与 `import-dir` 同一套判据） |
| deletions | ✓ | **只能**是 `"propose-only"`：盘上的文件被删/改名时，**树里的节点一个都不动**，只产出一条"待确认"提议（改名 = 新增 + 提议删旧）。**任何"自动删节点"的取值都判红** —— 工程铁律是"不许删除"，删除的认定只能由人做 |
| debounceMs | - | 文件事件合并窗口（毫秒，50–60000；缺省 800）。一次保存会触发多个文件系统事件，防抖把它们合成一批 |
| status | - | `watching`（缺省，守护中）/ `paused`（人按了暂停）/ `blocked`（本轮被挡住，如界面有未保存编辑；`note` 会写清原因）。缺省 = `watching` ⇒ **老数据不需要这个键** |
| note | - | 一句人话（为什么是 `blocked` 之类）。仅用于回显，不参与任何判定 |
| lastSyncAt | - | 上次成功同步的时刻（ISO 字符串）。**只有真的改过树才写**；它是"上次同步是什么时候"的唯一出处 |

**扫描快照不进这里**（这是本契约最要紧的一条规矩）："每个文件的 mtime/大小/指纹、对应的节点 id、
待确认提议、未转换清单"都在**旁路文件** `<name>/.bindings.json` 里（见 §5）。
理由：快照**每扫一次就会变** ⇒ 放进项目 JSON 等于守护进程每隔几秒就把用户数据搅脏一次 ✗。
它是**可再生的**：删掉它之后，同步会从树里各文件节点的 `origin`（§2.8）重建"哪个文件对应哪个节点"，
**不会重复建节点**。

> **典型来源**：CLI `bind-sync`（建绑定 / 同步一次 / 暂停 / 继续 / 解绑）。
> 写入方**只**经那一条命令改这个数组，别的手改方式没有校验保护（见 §3）。

| 字段 | 必填 | 说明 |
|------|------|------|
| meta.name | ✓ | 项目显示名（界面/导出用） |
| meta.author | - | 作者（当前恒为空串） |
| meta.version | - | **写入时的应用版本**，仅供追溯；解析方**不应**据此判断格式（格式看 `formatVersion`） |
| meta.formatVersion | ✓ | 数据格式版本（当前 **2**） |
| meta.rootMode | - | `"themes"` 时启用**主题模式**：根节点被当作容器（隐藏其方框与连线），各顶层子节点互相独立。缺省 = 单中心模式 |
| meta.layout | - | **主题左右分侧**：`{ "left": [主题id], "right": [主题id] }`（`left`/`right` 可各自缺省）。由 CLI `theme-layout <项目> --left a,b --right c,d` 写入，界面保存不丢；id 必须是**顶层主题**的 id。缺省 = 全部按树序排布。校验见 `src/schema.js`（`meta.layout` 必须是对象、两侧必须是数组、元素必须合法 id） |
| meta.themeOffsets | - | **顶层主题的拖拽偏移**：`{ "<顶层主题id>": { "x": 数, "y": 数 } }`。界面上「框选 → 拖动所选（整棵所属树）」的结果**就存在这里**（此前只活在渲染层，保存即丢 —— 用户报的"移动无法保存"）。坐标为**逻辑画布像素**、**相对该主题的自动布局位置**（不是绝对坐标：增删节点不会让旧偏移失效）。**只写非零项**；缺省 = 全部按自动布局。它只影响**呈现**，不改父子关系、不改分侧（分侧仍看 `meta.layout`）。校验见 `src/schema.js`（必须是对象、键是合法**顶层主题**id、值是 `{x,y}` 有限数字且绝对值 ≤ 20000） |
| meta.nodeOffsets | - | **节点/子树级的手工位置**：`{ "<子树根id>": { "x": 数, "y": 数 } }`（R2 期 1，2026-10-14 新增）。界面上「右键节点 → 拖动此子树」的结果**存在这里**；语义与 `meta.themeOffsets` **逐条相同**（逻辑画布像素、相对该根的自动布局位置、只写非零项、只影响呈现、不改父子关系），差别**只在键域**：`themeOffsets` 记**顶层主题**（root 的直接子节点），`nodeOffsets` 记**更深的节点 / 子树根**。同一 id 只住在**一个**键里（由渲染层按遍历现树分桶写回，见 `renderer/app-view.js` 的 `collectOffsets`）。**边界（写清免得误用）**：① 渲染时是**累加**的 —— 一个节点的屏幕位置 = 自动布局 + 它到根这条路上所有偏移根的和（深层子树与它所在主题的手工位置互不吞掉）；② **缺省 = 未偏移** ⇒ 老项目**零迁移**、`formatVersion` **不升**、`serializeTree()` 在没拖过时**一个键都不写**（与旧文件逐字节相同）；③ 校验与 `themeOffsets` **共用一处实现与同一张取值表**（`src/schema.js` 的 `validateOffsetMap` / `OFFSET_LIMIT`：对象、键合法 id、值 `{x,y}` 有限数字、绝对值 ≤ 20000） |
| format | ✓ | 固定 `"node_tree"` |
| data | ✓ | 根节点（id 固定 `root`） |
| assoc | - | **关联笔记**（N 元关联实体）集合，与 `data` 平级、**不属于节点树**。缺省 = 该项目没有任何关联（合法）。见 §2.6 |
| bindings | - | **工作区文件夹绑定**（R4）集合，与 `data` 平级、**不属于节点树**。**缺省 = 未绑定**（合法，且老项目不写这个键时语义与从前**完全一致**）。见 §1.5 |


## 2. 节点

```json
{
  "id": "my-node",
  "topic": "示例节点",
  "expanded": true,
  "detail": "这里是节点的详情（HTML）：\n1. ...",
  "tags": ["网络", "传输层"],
  "background": "#fff8e1",
  "images": [
    { "file": "assets/demo.png", "caption": "示意图：图里有什么、重点看什么", "source": "出处（可选）", "tags": ["示例"] }
  ],
  "files": [
    { "file": "attachments/notes.md", "caption": "完整笔记：何时引用、里面有什么", "source": "出处（可选）" }
  ],
  "links": [
    { "project": "other-project", "id": "some-node", "caption": "相关说明" }
  ],
  "qa": [
    { "q": "三次握手为什么是三次？", "a": "因为要同步双方的初始序号…", "at": "2026-10-10T12:00:00.000Z", "model": "deepseek-v4" }
  ],
  "origin": {
    "kind": "import",
    "src": "docs/notes/ch1.md",
    "sha256": "e39b89760f493677bd55a0c3c60789e0637cc80171372ed78e87311869ccf558",
    "at": "2026-10-10T04:07:00.727Z",
    "tool": "import-project"
  },
  "children": []
}
```

### 2.1 字段规则

| 字段 | 必填 | 类型 | 规则 |
|------|------|------|------|
| id | ✓ | string | 小写字母/数字/连字符（`^[a-z0-9][a-z0-9-]*$`），全树唯一，根为 `root` |
| topic | ✓ | string | 节点标题（非空）。可含**行内 Markdown**（`**加粗**`、`` `代码` ``）——界面渲染时转成 `<strong>`/`<code>`，**数据里仍是原文**（不写回 HTML，见下） |
| expanded | - | bool | 默认 true；false 表示收起 |
| detail | - | string | **HTML 片段**（见 §2.5）。渲染层以 `innerHTML` 注入，故必须写 HTML 标签才会呈现格式 |
| tags | - | array | 字符串数组；**每项必须是非空字符串**。用于分类与 `search --tag` |
| background | - | string | 节点底色。**当前为透传字段**：schema 不校验、界面与 CLI 均无设置入口，仅在序列化时原样保留 |
| images | - | array | 图片引用列表；**每项 file + caption 必填** |
| files | - | array | 附件引用列表；**每项 file + caption 必填** |
| links | - | array | 跨项目链接；**每项 project + id 必填** |
| localPath | - | string | **本机文件夹绝对路径**（如 `E:\markdown\M1`）。界面点击即用文件管理器打开；见下方说明 |
| qa | - | array | 「AI 问答记录」；**每项 `a`/`at` 必填**（`q` 可为空串、`model` 可选）。见 §2.7 |
| origin | - | object | 「来源指纹」：这棵树/这棵子树是从哪一份文档、哪一次导入来的（`kind`/`src`/`sha256`/`at` 必填、`tool` 可选）。见 §2.8 |
| children | - | array | 子节点（递归同构） |

> **`localPath` 是本格式里唯一的绝对路径**（与 §5「禁止绝对路径」的关系，别混淆）：
> 那条禁令针对的是**资源引用**（`images[].file` / `files[].file`）—— 它们要能在别的机器上解析，
> 所以只允许 `assets/`、`attachments/` 下的相对路径。而 `localPath` 是**目录快捷方式**：
> 它天生就是"**这台机器上的那个目录**"，没有可移植的含义（从文件夹结构建出来的树，每个结构节点挂一条）。
> 因此它**只校验形状**（非空 / 无换行 / ≤500 字符），**不校验存在性** —— 存在性依赖运行环境
> （盘没挂载、目录还没建都正常），把它做成校验条件会让"换台机器打开就连 `validate` 都红"。
> 换机器/换盘后本字段可能失效：**点开会明确报错，不会静默没反应**。
> 设置用 `add`/`edit` 的 `--local-path`，清除用 `--clear-local-path`；
> 界面上出现在**详情框的可点链接**与**右键菜单「📁 打开文件夹」**。

> **images 与 files 的区别**：`images` 是**图片**，界面中可直接预览/灯箱放大，文件存 `assets/`；
> `files` 是**任意附件**（md/pdf/zip…），文件存 `attachments/`：**md 在应用内联渲染预览、
> pdf 内嵌预览**（Chromium PDF viewer），其余类型交系统默认应用打开
> —— 见 `renderer/app-media.js` 的 `openFilePreview`。
> 两者都**必须**有 `caption` —— AI 读笔记时凭 caption 判断内容与是否引用，没有 caption 的
> 附件等于不可发现。

### 2.2 images 项

```json
{ "file": "assets/abc.png", "caption": "图里有什么、重点看什么", "source": "出处（可选）", "tags": ["标签1"] }
```

- `file`：相对 `projects/<name>/` 的路径（规范为 `assets/<文件名>`）。
- `caption`：**必填**。AI 阅读笔记时凭 caption 理解图片内容、决定是否引用。
- `source`：可选出处（文档名/页码/链接）。
- `tags`：可选标签数组。

> ✅ **`import-md` / `import-project` 会把 md 里的图片/附件引用真的搬进项目**（W19，2026-10-12）：
> 能解析到源文件（按 `md 同目录 → md 同目录同名文件 → 当前工作目录` 的顺序找，绝对路径直接用）⇒ 文件被
> **复制进** `projects/<项目>/assets|attachments/`（命名与图片格式规则与 `add-image` 同一条），
> `images[].file` / `files[].file` 写**项目内相对路径**；引用本来就指向项目内有效文件（如 export-md 的往返）
> ⇒ 原样保留、不重复复制。**解析不到 ⇒ 拒绝整份导入**并逐条点名（哪个节点 / 哪一条引用 / 原样路径 /
> 按序试过哪些路径），拒绝是干净的（判据在复制与写入之前：不建目录、不写盘）—— 出路见报文
> （把文件放到 md 同目录的 `assets/` 下、或先 `add-image`/`add-file` 再导、或把它改成远程链接/删掉）。
> **非本地引用**（`https:` / `data:` 等 scheme）**不复制、也不挂进 `images/files`**（`file` 只装项目内相对路径），
> 那一行按**正文**并入该节点 `detail` —— 内容不丢、`stats` 不被污染；`images/files` 里也不会再出现
> `data:` 占位图（从博客/编辑器导出的 Markdown 常夹带 **1×1 透明 GIF**，实测量级可到一篇笔记 128 处）；
> 不想留那些行就删 `detail` 里对应的一行（不再是"用 `remove-image` 清坏引用"那套）。

### 2.3 files 项

```json
{ "file": "attachments/abc.md", "caption": "该附件是什么、何时引用", "source": "出处（可选）" }
```

- `file`：相对 `projects/<name>/` 的路径（规范为 `attachments/<文件名>`）。
- `caption`：**必填**。说明该附件的内容与用途。
- `source`：可选出处。
- 通过 `add-file` / `remove-file` / `files` 命令维护。

### 2.4 detail 的语义：**HTML，不是 Markdown**

> ⚠️ **本节纠正一处长期存在的文档错误。** 旧版本文档称 detail 为"Markdown 语义、
> 渲染层转 HTML 展示"，**与实现不符**，曾误导 AI 写入 Markdown 从而渲染成字面量。

**实现事实（三重证据）**：

1. `renderer/app-detail-content.js` 渲染详情时执行 `dc.innerHTML = detail` —— 直接按 HTML 注入，无任何转换；
2. `renderer/editor.js` 保存时原样取编辑框文本，不做转换；
3. 全文搜索（`src/query.js` 的 `searchNodes`，`cli/commands/project.js` 的 `search` 只做转发）
   需**先剥掉 HTML 标签**（`convert.stripHtml`）再匹配 detail —— 反证存储值含标签。

**实测**：`comnet` 的含 detail 节点，**绝大多数为 HTML**（`<h3>/<p>/<b>/<ul>/<table>`），
Markdown 语法占比 **0%**。

> ⚠️ **这里原先写死了一个数（"133 个含 detail 节点"），已删 —— 它是错的，而且天生会漂。**
> 取证与更正见**该设计稿的同批只读核查记录**（工作产物，在 `.review/` 下那个**日期 + "设计核查"**的目录里，
> 报告与清单都在其中）—— 它的批次编号、条目编号（`A7` / `D1-1`）**只在这个版本库之外的工作目录里有效**，
> 所以**不把它们抄进这里** ✗。
> **正确读数现算，不许抄**：`node scripts/detail-census.js comnet`（脚本 `--json` 给机器读），
> 它打印的就是本节要的那个数；同一口径下它还会告诉你"含白名单标签 / 不含"各多少 ——
> **那 2~3 个"不含"的样本是"渲染期探测"规则的真值边界**（见 §2.4.1 末段）。
>
> **为什么写死的数一定错**：`projects/comnet/comnet.json` **会被并发会话改写** ⇒ 同一份文件在同一时刻就是**两个真值**
> （工作区那份 vs git `HEAD` 那份 —— 差了几百个节点）。所以这里**连"当前是多少"也不写**：
> 任何"写死一个数"的判据与叙述都会**因他人并发写而假红/假绿** ✗。要知道现在的数，**跑上面那条命令**。

**所以**：

| 场景 | 该写什么 |
|------|---------|
| 直接写 `--detail` | **HTML**，如 `--detail "<h3>标题</h3><ul><li>要点</li></ul>"` |
| `import-md` 导入 Markdown 文件 | 写 **Markdown**；导入时自动转换为 HTML 存储 |
| `--detail-md`（`add`/`edit` 的选项） | 写 **Markdown**；命令内转换为 HTML 存储 |
| `export-md` 导出 | 输出 **Markdown**（HTML → Markdown 转换） |

> **`import-md` 导入代码的两条硬规则**（2026-09-29 修完围栏缺陷后固化，都有单元测试守着）：
> 1. **围栏代码块是数据，不是结构**：` ``` ` … ` ``` ` 之间的内容一律原样进 detail，不参与标题/列表/表格/强调解析。
>    修复前它会被空行切断、`#include` 被当成 `<h1>`（实测一篇笔记 47 个块只有 8 个完整）——属静默损坏。
> 2. **标题层级要连续**：`src/markdown.js` 遇到层级跳跃会插一个 `（层级N）` 占位节点兜底
>    （源文件 `H2` 直接跳到 `H4` 时就会出现）。想让某个标题成为**目标父节点的直接子节点**，
>    在待导入的 md 里就用**一个 `#`（H1）** —— 因为导入时"层级差"是相对给定的父节点算的。
> 3. 已知的**唯一**文本归一化：每行行尾空白被去掉（`replace(/\s+$/, '')`），于是代码块里
>    "只由空格组成的行"会变成空行 —— 渲染等价，但逐字节 diff 时要知道这一点。
| 附件 `.md` 预览 | 按 Markdown 渲染（那是文件预览，与节点 detail 无关） |

**Markdown 只存在于"导入/导出边界"**，不是存储格式。转换由 `src/convert.js`
（`markdownToHtml` / `htmlToMarkdown`）与 `src/markdown.js` 承担。

> **写 HTML 时注意**：`markdownToHtml` 会把**裸 HTML 标签转义**（防注入）。因此走 Markdown
> 路径（`--detail-md` / `import-md`）时不要在 Markdown 里混写 HTML 标签，否则标签会显示为字面量。
> 反之，直接写 `--detail` 时内容是 HTML，不会被转义——**两条路径不要混用**。

#### 2.4.1 渲染层的契约：**HTML 优先**（2026-10-14 钉死）

**契约（一句话）**：`detail` 落盘时是 **HTML**，渲染层就**按 HTML 注入**它 ——
正文的**唯一**渲染点是 `renderer/app-detail-content.js` 里的 `dc.innerHTML = detail`，
**不做任何转换**（不解析、不重排、不转义）。

**为什么要把这条写死**（不是风格问题，是"会不会砸掉用户既有内容"）：

| 若有人把这一行改成 | 后果 | 证据 |
|---|---|---|
| 一律走 `markdownToHtml`（`src/convert.js`） | 它**先整体转义再套行内语法** ⇒ 既有 HTML 节点的标签会**显示成一堆字面量**（`<h3>`、`</p>`…） | `src/convert.js` 文件头自述；§2.4 的三重证据 |
| 靠"看起来像 Markdown"**猜**路径 | 猜测规则一改，同一份数据渲染出两种样子（§2.4 已警告"两条路径不要混用"） | 上面那条 ⚠️ |

**实测基线**：真实项目 `comnet` 的含 `detail` 节点**绝大多数是 HTML、Markdown 占比 0%**
（= 本节上面的读数）⇒ 把它改走 Markdown 路径 = **一次性砸掉这些节点的呈现**。
**规模现算，不许抄数**：`node scripts/detail-census.js comnet`（**这条判据不许把数写死** —— 见上面那条 ⚠️）。

**两条机械守卫**（都不是靠人读文档）：

1. **结构断言**（`tests/detail-html-contract.test.js`）：`renderer/app-detail-content.js`
   里**零** `markdownToHtml` / `mdBlock` / `mdInline` 调用（剥注释后按实现形状扫），
   且"把 `detail` 注入 `innerHTML`"那一跳必须在；注入一次违规源码 ⇒ 断言**必红**。
2. **冒烟真帧判据**（`scripts/smoke/47-detail-html-links.js`）：造一个 HTML `detail` 夹具渲染进真窗口
   ⇒ ① 真帧里那个 `<h3>` 位置命中它自己且有墨；② **画出来的文字里不含字面标签**
   （`<h3` / `</h3` / `<b>` 这类串一个都不许出现在正文可见文本里）。

**两条路径怎么选**（详情渲染的**后续批**，不在本条；设计稿见
`.review/20261014-节点详情Markdown渲染/设计.md` §①）：有 `items[]` ⇒ `renderDetail(items)`（真源）；
`detailMode:'rich'` ⇒ HTML；其余按**渲染期探测**（只看白名单内的标签，不是"含 `<` 就算 HTML"）
显式二选一 —— **显式选择**，不许猜 ✗。

### 2.5 links 项

```json
{ "project": "other-project", "id": "some-node", "caption": "说明（可选）" }
```

- `project`：目标项目目录名（`projects/<project>/`）。
- `id`：目标节点 id。
- 校验（悬挂链接检测）：validate 会检查 `(project, id)` 是否真实存在；
  目标项目文件不存在或目标节点不存在 → 报错。
- 注意：`links` 是**跨项目**引用；**同项目内**节点的引用关系由 `relations.js` 按
  `links` 反查得到（`backlinks` / `related`），不需要额外字段。

### 2.6 assoc 项（「关联笔记」= N 元关联实体）

```json
{
  "id": "a-lz3k7q",
  "title": "三次握手与可靠传输的关系",
  "members": [
    { "project": "comnet", "id": "tcp-handshake" },
    { "project": "comnet", "id": "tcp-reliable" }
  ],
  "note": "<p><strong>先建连</strong>，再在其上做可靠传输。</p>"
}
```

| 字段 | 必填 | 类型 | 规则 |
|------|------|------|------|
| id | ✓ | string | 与节点 id 同一套规范（`^[a-z0-9][a-z0-9-]*$`），**在 `assoc` 集合内唯一**。生成器用 `a-` 前缀（`a-` + 时间戳 base36 + 随机后缀），便于与节点 id 区分 |
| title | - | string | 这篇关联的标题。缺省时界面/CLI 用成员主题拼接出「有效标题」（`A ↔ B`）——那只是**视图派生值**，不落盘 |
| members | ✓ | array | 成员列表：**至少 2 个**且**不可重复**（同一 `project` + `id` 出现两次即报错）。每项含 `project`（项目目录名）+ `id`（节点 id），两者都必填 |
| note | - | string | 关联正文。**HTML**，与节点 `detail` 同约定（见 §2.5）；Markdown 只出现在命令行边界（`assoc-add`/`assoc-edit` 的 `--note-md`，命令内转 HTML 后存储） |

**与 `links` 的分工（这是本集合存在的唯一理由）**

`links` 是**逐条声明的有向边**：图结构上它完全能表达三角关系与两两互指，
所以"图论上能不能表达"不是问题所在。`links` 表达不了的是
**「把若干节点的关联当成一个对象」** —— 而"介绍二者/多者之间关联知识"的笔记
需要的恰恰是这个对象：

| 挂在某条 `links` 边上 | 独立实体 `assoc` |
|----------------------|-----------------|
| 标题只能写成边的两端，**第三个成员在标题里消失** | 标题属于整篇关联，N 个成员平等 |
| 边上只有 `caption` 一个**受支持**的说明字段：N 个成员、正文、独立生命周期都放不下。<br>（2026-10-12 之前，重复 `link` 还会**静默抹掉**边上的 `caption`/`note` —— 那是**数据丢失**，已修，见 `CHANGELOG.md` `[Unreleased]` 的 K8 条；修完仍然只解决"别弄坏"，没解决"表达不了"） | 关联有独立 id 与独立生命周期，改 `links` 不影响它 |
| `unlink` 会让笔记**陪葬** | 成员由 `--members` 单独维护，与 `unlink` 无关 |

> 三条都是**实测结论**，不是推测；回归断言见 `scripts/cli-integration.js` 的
> 「关联笔记」段与 `scripts/smoke/10-assoc.js`。

**N 元的实际含义**：成员可跨项目（`项目/节点id`，如 `comnet/dns`），
且从**任一成员**都能查到同一篇关联（`assoc-list --node <id>`），
界面里也从任一成员的「相关知识点」区进入同一个二级页面。

**校验**（`src/schema.js` + `src/assoc.js`，`validate` / `validate-all` 都会报）：

1. **结构**：`assoc` 必须是数组；每项 id 非空且合规范、`title`/`note` 是字符串、
   `members` 是数组且 ≥2 个、成员每项有 `project`+`id`、同一集合内 id 不重复、
   同一关联内成员不重复（结构问题由 `assoc.validateAll` 报）。
2. **悬挂关联成员**：成员指向的节点必须**真实存在**，检测与**悬挂链接同一处逻辑**。
   判定真值分两种：**本项目**成员以**即将落盘的那份 data** 为准（不是磁盘 —— 读盘会把
   "刚删掉的节点"算成还在，闸门因此慢一步漏判）；**跨项目**成员只能读盘（磁盘是唯一真值）。
   目标项目不存在 / 目标节点不存在 / 项目文件不可读，三种都报错。
   `assoc-add` / `assoc-edit --members` 在写入前也会逐个检查成员存在，**不让你造出悬挂关联**。
3. **删节点会留下悬挂成员吗**：会 —— 所以 **CLI** 的 `remove <项目> <id>` 在发现被删（子）树
   被关联引用时**拒绝执行**并给出两条路（因为一旦写下去，该项目**所有**写命令都会被闸门挡住）：
   `remove <项目> <id> --clean-assoc`（删节点并同步剪掉这些关联里的该成员，
   剪完不足 2 个成员的关联整篇删除）或 `assoc-prune <项目> --nodes <id>`（先摘引用再单独删节点）。
   **界面**的删除走同一条规约：先弹确认列出影响面，再经 IPC `app:pre-delete-cleanup` 让 **CLI 在磁盘上**
   用 `links-prune` + `assoc-prune` 剪干净，**成功后才删节点**（清理失败就不删）。
   清理完渲染层还把**内存树**里指向被删节点的链接一并摘掉，否则 `save()` 会把悬挂链接写回磁盘（实测）。
4. **链接也会悬空（同项目，或别的项目删了节点）**：`remove` 同样会对同项目入边链接拒绝执行，
   需 `--clean-links`；而"**别的项目**把目标节点删掉"这种情况本项目无从预防，只能事后修 ——
   用 **`links-prune <项目> [--nodes a,b] [--dry-run]`**（默认只删**确认不存在**的目标，
   目标项目读不出来时只警告、不猜）。没有它，被判红的本项目**无法自救**（界面上没有删链接的入口）。
   更一般地，**`assoc-prune <项目> [--nodes a,b] [--dry-run]`** 可清理已存在的悬挂成员：
   默认只剪**确认不存在**的成员，项目读不出来（损坏/权限）的成员单独列出警告而**不当作悬空**；
   全清空时 `assoc` 键一并去掉（与 `assoc-remove` 同一约定）。

**归属（重要）**：`assoc` 的**批量作者仍是 AI/CLI**（跨项目、脚本化、成批生成都走 CLI），
但界面**已有创建入口**：关联视图顶部的「关联信息」编辑条 →「📝 新建关联笔记」
（成员用小标签列出、中心节点预置、≥2 个成员）—— 写操作仍是 CLI `assoc-add`，
渲染层不直接改盘、也不自己拼 HTML。
**二级页面**本身仍然**只能从节点详情的「相关知识点」区进入**（它不是节点、不在树里、命令面板也搜不到），
页内可**编辑标题与正文**，走的是 CLI `assoc-edit`。
因为**节点树由渲染层拥有、而 assoc 由 CLI 拥有**，保存链路上有两道保护：

- 渲染层 `serializeTree` 会把内存里的 `state.assoc` **原样带出**（漏掉即"保存就抹掉"）；
- 主进程 `project:save` 若发现渲染层没带 `assoc`，会**从磁盘现有文件取回**，不用空值覆盖
  —— 防止 AI 刚写的笔记被一次界面保存清掉。

**向后兼容**：`assoc` 是 `formatVersion` 2 内**只增不改**的顶层可选集合 ——
缺失即"没有关联"（合法）；旧文件**不需要迁移**，`formatVersion` 仍为 2。
全部删空时 `assoc-remove` 会把 `assoc` 键**整个去掉**（不留空数组噪音，与旧格式完全一致）。
`export-json` / `import-json`（aimap v1）同样携带 `assoc`（仅非空时写入，旧包形状不变），
故"无损备份/迁移"路径不会丢关联笔记。

### 2.7 qa 项（「AI 问答记录」）

```json
{ "q": "三次握手为什么是三次？", "a": "因为要同步双方的初始序号…", "at": "2026-10-10T12:00:00.000Z", "model": "deepseek-v4" }
```

| 字段 | 必填 | 类型 | 规则 |
|------|------|------|------|
| q | ✓（可为空串） | string | 提问原文。**允许空串** —— "解释这个节点"本来就没有提问文本，用真值判定会把这种合法问答误杀 |
| a | ✓ | string | 回答原文，**必须非空**（一条没有回答的记录毫无意义，而且它会让"AI 产出是不是落进去了"永远为真 —— 本工程最忌的假绿） |
| at | ✓ | string | ISO 时间（非空字符串），由**调用方**给 ⇒ 界面上显示的时间就是落盘时间（同一件事不要两个时间） |
| model | - | string | 产出这条回答的模型名。**取不到就不写** —— 编一个模型名比没有更坏（后人会以为那是真的） |

- **它回答什么**：「这个节点的这一段结论是哪一次 AI 交流得来的」。卖点 5 点名的字段。
- **是可选字段，不升 `formatVersion`**：缺失即"从没被 AI 问过"（合法），旧文件**不需要迁移**。
- **写入走 `ask-apply`**（见 `docs/CLI.md`）：一次调用里**同时**追加 `qa` 记录与 `detail` 末尾那一段
  （带 `🤖 AI 问答` 来源标记与时间）。**追加，不覆盖** —— 问答是流水，第二次写入抹掉第一次
  就是把 AI 产出变成"只有最后一次"。完全相同的条目（q/a/at 三项一致）视为重复 ⇒ 幂等不追加。
- **读得到**：`get --json`（总是带出，不受 `--detail` 影响）与 MCP 的 `get_node` 都能读到它；
  `read` 视图在 **brief 档也带**（它是"这段结论是哪次交流得来的"，属导航信息；真嫌大就上 `skeleton`）。
- 文本形状（`detail` 里那段 HTML 长什么样、子节点标题怎么从回答派生）只有一处实现：`src/qa.js`。

**向后兼容**：`qa` 与 `tags`/`links`/`localPath` 同一档 —— 只增不改的**节点级可选数组**，
`formatVersion` 仍为 2；`validate` 只校验**形状**（上面的四条），不校验内容。

### 2.8 origin 项（「来源指纹」）

```json
{ "kind": "import", "src": "docs/notes/ch1.md", "sha256": "e39b8976…（64 位十六进制）", "at": "2026-10-10T04:07:00.727Z", "tool": "import-project" }
```

| 字段 | 必填 | 类型 | 规则 |
|------|------|------|------|
| kind | ✓ | string | 来源类型。当前**只有** `"import"`（将来加别的来源时才扩展；写死具体值而不是"任意字符串"，是为了让消费者能穷举） |
| src | ✓ | string | 来源引用：**相对工程根**的 POSIX 路径（如 `docs/notes/ch1.md`）；跨盘时退回绝对路径；将来支持 URL 时就是 URL。**仅供追溯**，不参与任何路径安全判定 |
| sha256 | ✓ | string | **64 位小写十六进制** = 规范化后**提纲文本**的 sha256（见下"指纹算的是什么"） |
| at | ✓ | string | ISO 时间（非空）。由调用方给 ⇒ 就是这次导入发生的时刻 |
| tool | - | string | 哪条命令写的（`import-project` / `import-md` / `import-dir`）。取不到就不写 —— 编一个比没有更坏 |

- **它回答什么**：「这棵树（或这棵子树）是从哪一份文档、哪一次导入来的」——也就是
  **"这份文件我导过没有"**。
- **为什么必须有它**：节点 id 由 `Date.now()` + 随机数生成（`src/markdown.js` 的 `idGen`）
  ⇒ **同一份文档导入两次会得到两棵不相交的树**：内容一模一样，但每个节点的 id 都是新的。
  于是事后无法凭内容判断"这份导过了没有"，任何批量/整库导入都做不到**幂等**（再跑一遍只会又长一棵树）。
  `src` + `sha256` 是唯一能认出它的判据。
- **写在哪**：挂在**一次导入产生的那几棵子树的根**上，不是每个节点都抄一遍
  ⇒ 条数 ≈ 导入次数（不是节点数），文件不会膨胀：
  · `import-project`：挂在新项目的**根节点**（一次导入只留一个痕）；
  · `import-md`：挂在这次追加进去的**每个顶层子树根**（`#` 级标题那几棵）；
  · **`import-dir`（整库导入，批 5）：两档各留一条痕** —— 项目**根节点**写一份**目录清单指纹**
    （`src` = 源目录、`sha256` = 清单哈希 = 按相对路径排序的 `相对路径 sha256` 每行一条再取哈希），
    用来回答"**这个目录**导过没有"；**每个文件节点**再写一份自己的 `{src, sha256}`，
    用来回答"**这个文件**导过没有"（同一个文件被 `import-md`/`import-project` 导到别处也认得出）。
    清单用的是**相对源目录**的路径（不是 `origin.src` 那种含绝对位置的引用）：指纹要回答的是
    "这份目录内容变没变"，位置由 `src` 自己承担 ✓。两档的形状完全一样（同一套校验），
    且都只准经 `src/doc-import.js` 的 `makeOrigin` / `makeDirOrigin` 生成。
- **指纹算的是什么**：**规范化后的提纲文本**（CRLF/CR → LF、剥 BOM）的 sha256 ——
  不是原始文件字节。所以同一份内容存成 CRLF、或带 BOM，指纹**一样**（重导不会被误判成新内容 ✓），
  而**改一个字节就变** ✓。规范化与指纹只有一处实现：`src/doc-import.js` 的
  `normalizeOutline` / `outlineSha256` / `makeOrigin`（写入方不许自己拼 origin）。
- ⚠️ **同一个规范化必须同时喂给"建树用的正文"**（本轮修的一个静默数据丢失，2026-10-10）：
  `normalizeOutline` 原先只被 `import-project` 那条路调（在 `docToOutline` 里），而 `import-md`
  拿的是 `fs.readFileSync` 的**原文** ⇒ 同一份 BOM 文件经两条路得到**两棵不同的树**：
  带 BOM 的 `# 第一本书\n正文一\n\n# 第二本书\n正文二` 经 `import-md` 导入后**只剩「第二本书」**
  （第一个标题被当成正文吞掉，因为 `markdown.js` 的 `detectMode` 要求首行是 `#`），
  而去掉 BOM 的同一内容两个标题都在 ✓。现在 `import-md` 先 `normalizeOutline` 再建树与算指纹
  ⇒ **正文与指纹共用同一份规范化**（这正是上面那句"只有一处实现"的全部含义）。
- **体量闸门**（`describeOversizeSource`，与导入格式无关的**入参约束**）：单文件超过上限常量
  `MAX_SOURCE_MB` 时**响亮拒绝**并给三条出路（拆文件 / 转成压缩格式 / 只取需要的部分），
  **不读进内存**（整份读进来会把进程拖垮 ⇒ 那正是"命令莫名退出、什么都没打印"的成因 ✗）。
  该常量只有一份（`src/doc-import.js`），三条导入路（`import-project` / `import-md` / `import-dir`）共用同一个判据；
  **具体数值看常量本身**（文档不抄 —— 抄一份就是第二份会漂移的副本 ✗）。
  **整库导入另加一条**：可导入文件的**合计体积**也吃同一个 `MAX_SOURCE_MB`（`describeDirOversize`，
  整棵树要先在内存里建好再一次性原子写 ⇒ 总有一个瞬间它在内存里），外加一条**文件数上限**
  （`MAX_IMPORT_FILES_DEFAULT`，`--max-files` 覆盖，`describeTooManyFiles`）。两条都在**读文件之前**判、
  都给可执行的出路（分批 / `--ext` 缩小范围 / 明确写大上限）。
- **幂等闸门（写命令的行为，不是格式约束）**：`import-project` / `import-md` 在写盘**之前**
  比 `src` + `sha256`（`import-project` 与 `import-dir` 扫**全部项目**，`import-md` 扫**本项目**）：
  命中就**拒绝**并非 0 退出，报文里**指名**上一次导到哪个项目的哪个节点，并给出 `--force` 出口。
  **两个都要相同才算同一份**：只比 `sha256` 会把"两份内容恰好相同的不同文件"误判成重复；
  只比 `src` 则文件被改过就判不出来（而那正是最该拦住的情形）。
  `import-dir` 的粒度取舍：**整个目录重复导 ⇒ 整体拒绝**（推荐的那档 —— "重复导入不可察觉的污染"
  在这里是整棵树，按文件粒度放行会让人自己判断每一条，反而更容易漏）；同时**任一文件**命中文件级
  指纹也拒绝并逐条点名。判据只有一处实现（`originMatches`；全库查表用同一口径的 `originKey`）。
- **读得到**：`get --json`（**总是带出**，不受 `--detail` 影响）、`read --json`（`--brief` 带、
  `--skeleton` 省 —— 与 `localPath`/`qa` 同一档）、MCP 的 `get_node`；
  `stats` 报 `originNodes`（多少节点带来源）与 `originSources`（涉及几份**不同**来源）——
  同一份来源被 `--force` 导两次时节点数涨、来源数不涨，**一眼看得出那是重复导的**。

**向后兼容**：`origin` 是**可选对象字段**，`formatVersion` 仍为 2，旧文件**不需要迁移**
（没有它 = "不是从文件导进来的"，合法）。`validate` 只校验**形状**（上面的五项），
**不重算哈希** —— 重算要把源文档读回来，而它可能早已不在本机/已被改过，
那会把"数据问题"变成"环境问题"（同 `localPath` 不校验存在性的理由）。

### 2.9 Obsidian 库直进（W12）的**落点契约** —— 不新增字段，只规定"什么变什么"

> **为什么写在这里**：W12 只规定"要接成关联、落 caption 或**等价字段**"，**没写死落到哪个字段**。
> 这里把它钉成契约（否则下一个人会另发明一套），并说明**为什么不需要新字段**。
> 一句话：**它就是既有 `links[]` / `tags` / `files[]` 三种字段的组合**，一个 `formatVersion` 都不升。

`import-dir --vault`（目录里有 `.obsidian/` 时**自动**打开；`--no-vault` 显式关掉）把一个 vault 转成：

| 源里的东西 | 落到哪 | 具体形状 |
|---|---|---|
| 目录 / 子目录 / `.md` 文件 | **既有节点树**（与 `import-dir` **同一条链**，逐字节同一套规则） | 子目录 = 容器节点、文件 = 文件节点（标题取文件名去扩展名），文档自己的标题在它下面 |
| `[[页]]` / `[[页\|别名]]` / `[[页#标题]]` | **`links[]`**（第 2.5 节那个字段，**不新增关系类型**） | `{ project: <本次导入的项目名>, id: <目标节点 id>, caption: "…" }`。带 `#标题` 时 `id` 指向**那篇笔记里对应的标题节点**（不是文件节点）；`caption` 记下"源笔记标题 + **原样写法**"（别名与片段都在里面）⇒ 满足第 2.5 节"链接必须有 caption"的既有要求 |
| `![[图.png]]` / `![[附件.pdf]]`（有扩展名） | **`files[]`**（走既有**资源行**语法 ⇒ 由 `resolveImportRefs` 落地，命名/格式闸门与 `add-image` 同一处） | 落成项目内文件 ⇒ `{file:"attachments/<新名>", caption:"…"}`；落不成 ⇒ **摘下来 + 按正文保留 + 逐条点名**（与第 2.2/2.3 节"不留悬空引用"同一条规矩） |
| `![[另一篇笔记]]`（无扩展名） | **`links[]`**（按链接处理）+ 报告里标 `embed-note` | 本批**不做** transclusion（正文不合并）—— **原文一字不动**，只在报告里逐条列出 |
| frontmatter `tags:` / `tag:` | **`node.tags`**（第 2.1 节那个字段，与 `--tags` 同一套机制） | 落在**那篇笔记的文件节点**上；`#` 前缀剥掉（`#工具` 与 `tags: [工具]` 是同一件事）；去重但保序 |
| frontmatter `aliases:` / `alias:` | **不落盘**（只做**候选名**） | `[[别名]]` 能解析到那篇笔记；别名本身进导入报告的 `aliases` 列表（把它写进节点会造出第二份"标题"，而改名是另一件事） |
| frontmatter 其它键（`created` / `title` …） | **不落盘** | 只在报告的 `frontmatter[].other` 里列出键名（不猜语义、不塞进任何字段） |
| `[[目标不存在的页]]` / 同名多篇 / 目标不在本批范围 | **什么都不写**，进报告 `dangling[]` / `ambiguous[]` | ⚠️ **绝不写悬空链接**：写一条指向不存在节点的 `links` 会让该项目**所有写命令**被悬挂检测挡住（第 3 节第 8 条）⇒ 那才是真的"导入即坏库" |

**为什么不去 `assoc`**：`assoc`（第 2.6 节）是"把若干节点的关联当成**一个对象**"时才有必要
（有自己的标题/正文/N 元）。`[[…]]` 是**逐条声明的有向边**，正是 `links[]` 的形状；
两处都表达同一件事会立刻产生"哪一份才是真值"的问题。**同一批内的链接**因此也走 `links[]` ——
"同一次导入里的链接接成关联"说的是**目标节点都在这一批里**（所以能直接算出 `id`），不是换一种实体。

**同项目 `links` 合法吗**：合法。第 2.5 节那句"`links` 是跨项目引用"描述的是它的**常见用途**，
而校验判据（`schema.validateProject(data, projectsRoot, selfProject)`）对**同项目**的
`(project, id)` 用的是"**即将落盘的那份 data**"当唯一真值 —— 所以刚建出来的节点当轮就认得，
`validate` 通过（这一条有单测与集成断言各一处钉着：`tests/vault.test.js` 的"与既有契约相容"组）。

**幂等**：走既有 `origin`（第 2.8 节）。⚠️ 两条导入的**指纹来源不同**：
`--no-vault` 那一路算的是**原始正文**，`--vault` 那一路算的是**剥掉 frontmatter、消化掉 wiki 语法之后**的正文
（`src/doc-import.js` 的 `applyVault` 把转换后的正文交给同一处 `makeOrigin`）——
同一个目录用两种模式各导一次，会被当成**两份不同的来源**（这是**对的**：落盘内容确实不同）。

**错误与报告**：`import-dir --json` 的 `vault` 段是**读数**（`files` / `linkTotal` / `linked` /
`headingLinks` / `aliasLinks` / `embedLinks` / `danglingTotal` / `taggedFiles` / `tags` / `aliases` /
`links[]` / `dangling[]` / `ambiguous[]` / `embedNotes[]` / `resourceUnresolved[]` / `notes[]`），
**没开 vault 时该段为 `null`**（默认档的报告与从前逐字节相同）。

## 3. 校验规则（schema.js）

1. 顶层必须有 meta/format/data。
2. format 必须为 `node_tree`。
3. 每个节点：id 规范 + 全树唯一；topic 非空；children 是数组。
4. detail 必须是字符串。
5. tags 必须是数组，且每项为非空字符串。
6. images 每项 file + caption 非空。
7. files 每项 file + caption 非空。
8. links 每项 project + id 非空；目标 (project,id) 存在（悬挂链接检测）。
9. `assoc`（缺省合法）必须是数组；每项 id 规范且集合内唯一、members 是数组且 ≥2 个不重复成员、
   成员每项 project + id 非空；每个成员指向的节点存在（**悬挂关联成员检测**，与悬挂链接同处逻辑；
   修好悬挂成员用 `assoc-prune`）。见 §2.6。
10. meta.formatVersion 为 2（缺省视为合法；**无 v1 迁移分支**）。
11. 整树无环（**迭代式检测**，不用递归，避免深树爆栈）。
12. **detail 内容不做 HTML/Markdown 校验**：任何字符串都合法（含义见 §2.5）。
13. `qa`（缺省合法）必须是数组；每项 `a` 为非空字符串、`at` 为非空字符串（ISO 时间），
    `q` 若存在必须是字符串（**允许空串**）、`model` 若存在必须是字符串。见 §2.7。
14. `origin`（缺省合法）必须是对象；`kind` 必须为 `"import"`、`src` 为非空字符串、
    `sha256` 为 64 位小写十六进制、`at` 为非空字符串，`tool` 若存在必须是字符串。
    **不校验 src 指向的文件是否存在**（同 §2.1 的 localPath：那是环境问题）。见 §2.8。

## 4. 版本演进

| 版本 | 说明 | 兼容性 |
|------|------|--------|
| 2（当前） | 现行格式 | — |

> **纠正**：旧版本文档称"v1→v2 时 detail 由 HTML 改为 Markdown 语义、旧数据读取时懒转换"。
> **代码中不存在该迁移**：`src/schema.js` 只校验 `formatVersion === 2`（缺省视为合法），
> 没有任何 v1 分支或 `htmlToMarkdown` 懒转换；且 detail 至今仍是 HTML（见 §2.5）。
> `convert.js` 的 HTML⇄Markdown 只服务于 `import-md`/`export-md` 与附件预览。

**兼容承诺**：
- **只增不改**。新增可选字段不递增 `formatVersion`——旧解析器忽略未知字段即可正常工作。
- **破坏性变更**（改字段语义、删字段、改必填性）必须递增 `formatVersion`，并在
  `src/schema.js` 加迁移分支、同步本文档与 `CHANGELOG.md`。
- `meta.version`（应用版本）**不是**格式版本，解析方不应据此判断格式。
- 字段顺序无意义；解析方不得依赖 JSON 键序。

## 5. 文件与目录约定

```
projects/
└── <name>/
    ├── <name>.json      # 项目数据（唯一真源）
    ├── assets/          # 图片文件（节点 images[].file 指向这里）
    ├── attachments/     # 附件文件（节点 files[].file 指向这里）
    └── .ui-state.json   # 运行时协调信号（「界面有未保存编辑」），不是数据；可随时删
                         # 键：schemaVersion / project / dirty / uiPid / updatedAt
                         #     + seenVersion / baseVersion（v0.20 增：两个**盘上版本指纹**，
                         #       与写盘闸门同一值空间 —— 读方拿项目文件当前指纹与它们比字符串，
                         #       即可判「界面所见落后盘上多少」；缺值一律空串，老文件不编版本）
    └── .changes.jsonl   # 变更日志（谁/何时/改了哪些对象，多路同时编辑的事前避让依据），不是数据；
                         # 由唯一写盘出口顺带产生、有界（最近 N 条）、不进 export-json；可随时删
    └── .bindings.json   # 绑定工作区文件夹（§1.5）的**扫描快照**，不是数据；可随时删
                         # 键：schemaVersion / binding / dir / lastSyncAt /
                         #     files{相对路径 → {mtimeMs,size,sha256,format,nodeId,topic}} /
                         #     unconverted[]（转不了的文件，逐条点名）/ 
                         #     pendingDeletions[]（待确认的删除提议：rel/nodeId/topic/at）
```

- 项目名 = 目录名 = JSON 文件名（三处一致）。
- 图片只存 `assets/`、附件只存 `attachments/`，一律用相对路径引用；**禁止绝对路径**。
- 目录按需创建：无图片则无 `assets/`，无附件则无 `attachments/`（空目录不入库）。
- **数据目录里只应有上面这几项**。它是**用户数据目录**，不是工作区：脚本、分析稿、一次性
  工具**不要**放进来（实测曾有一个 26 KB 的 `build.js` 躺在里面、无人知道来历，且**没有任何门禁管**
  —— G8 刻意跳过 `projects/`）。`npm run check:docs` 会**列出**契约未声明的项提醒确认（不判红）。
  需要长期保留的脚本请移入 `.review/`（工作产物区）。
- 写盘一律走**原子写**（`src/data-store.js` 的 `writeFileAtomic`：同目录临时文件 → `fsync`
  → `rename`），保证中断不产生半截文件；解析时剥离 UTF-8 BOM。
- **路径穿越不在 `file` 字段的校验范围内**：`src/schema.js` 只要求 `file` 是**非空字符串**，
  `../` 之类的相对路径**能通过 `validate`**（实测：把 `files[0].file` 写成 `../../evil.md`，
  `validate` 仍报"校验通过"）。真正的拦截点在 `import-json` 解包资源时 ——
  `src/bundle.js` 的 `isSafeRelPath` 要求资源路径解析后仍在目标项目目录内部。
  即：`validate` **不做**此校验，别把它当成路径穿越的防线。

## 6. 导出语义（export-md）

- heading 格式：`#` 根 → `##` 一层 → `###` 二层……
- list 格式：缩进 + `- `。
- `--with-detail`：节点 detail 转为 `> 引用块` 跟在标题行后。
- 导入（import-md）为反向：heading 层级 → 节点树；非标题行并入最近标题节点的 detail。

> **不含 `assoc`**：`export-md` 导出的是**节点树**，`assoc` 是项目级集合、不在树里，故不进入
> Markdown 导出。需要连关联笔记一起迁移/备份请用 **`export-json`**（aimap v1，见 §2.6）。
