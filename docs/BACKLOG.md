## W4｜**混合检索与"权重怎么处理"** ⭐（用户点出的真问题 ✓）

- **核心主张**：**不要**把多个维度硬塞进一个分数 ✗ —— 分两层：
  1. **硬过滤**（正交、无权重 ✓）：范围（`--scope`）/ 标签 / 时间窗 / 节点种类 ✓；
  2. **排序信号**（各自独立成一路 ✓）：字面匹配（含**复用** `src/palette-rank.js` 的模糊排序 ✓）/ 标签相似 / **图距离**（links+assoc 的跳数 ✓）/ **时效**（W2 ✓）/ **来源可信度**（人写的 vs 导入的 `origin` ✓）/ 语义（W3，可选 ✓）。
- **融合方式（推荐）**：**RRF（倒数排名融合）** ✓ —— 每路各自出排名 ⇒ 按 `Σ 1/(k+rank)` 融合 ✓。好处：**不含量纲、不需要归一化、不写魔数** ✓（这正是"权重怎么处理"最省事的正解 ✓）。
- **权重仍要可调** ✓：`--weights text=1,graph=.5,time=.2,semantic=1`（默认一套写进注释并说明理由 ✓）+ 预设 `--mode balanced|recent|conceptual` ✓。
- **归因必须可见** ✓：`--explain` 输出"这条命中由哪几路贡献、各自什么排名"✓ —— **AI 才敢据此推理** ✓，人也能判断权重合不合理 ✓。
- **⭐ 权重的验证办法（关键 ✓）**：建一个**黄金查询集**（15–30 条真实问题 + 期望命中 ✓，放 `.review/` 或 `tests/fixtures/` ✓）⇒ **改权重就跑它，给前后对比数字** ✓。没有这个，调权重就是玄学 ✗。
- **验收判据**：`--explain` 可见每路贡献 ✓；黄金集能一键跑 ✓；改权重有前后对比 ✓；注入"某一路恒空"⇒ 对应断言语义红 ✓。
